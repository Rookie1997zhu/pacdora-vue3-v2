1. 目标与非目标

目标

  • 统一自研、Pacdora、Packative 最终进入系统的几何语义。
  • 自研 Geometry Core 成为正式计算主干。
  • 支持固定规格资产和参数化模板两类资产。
  • 验证、审批、导出绑定同一份不可变 GeometryDocument。
  • 材料工艺配置、尺寸适用域、打样和版本可追溯。
  • 先完成一个盒型生产闭环，再按结构家族扩展。

非目标

  • 不重写整个项目，不替换现有技术栈和部署架构。
  • 不复制第三方私有算法；外部资产按来源和授权使用。
  • 不一次性实现所有 ECMA/FEFCO 结构。
  • 不把 3D 外观或动画等同生产验证。

4. 模板注册与生成器体系

保留并规范现有 parametric、fixed_snapshot、model_only 三类：

  • parametric：通过生成器重新计算；声明输入 schema、尺寸域、材料约束和验证证据。
  • fixed_snapshot：固定尺寸几何；允许只读预览，不允许任意缩放冒充新刀版。
  • model_only：只有 3D 网格；只允许预览，不得反推为生产级二维刀版。

Generator 接口建议

interface BoxcraftGenerator {
  id: string;
  version: string;
  family: string;
  inputSchema: GeneratorInputSchema;
  validateInput(input: unknown): ValidationResult;
  generate(input: NormalizedInput): GeometryDocument;
  getSupportedDomain(): SupportedDomain;
  getCapabilities(): GeneratorCapabilities;
}

相同生成器版本、输入、材料工艺配置必须产生相同规范化几何。生成器不能静默读取当前模板版本、替换参数或回退到默认盒型。

外部适配器

  • Pacdora Adapter：解析已有 geometry JSON，保留来源、单位和固定规格属性；不伪装为原生参数化生成器。
  • Packative SVG Adapter：解析 SVG path、viewBox、物理宽高、transform、Cutting/Creasing 语义；单位推导失败时只允许预览。
  • Mesh Adapter：用于 3D 网格预览，不自动反推生产级面板拓扑。

适配器应报告 unsupportedFeatures、conversionLoss、unitConfidence。若曲线、语义或结构关系不能无损表达，工程导出应被阻断。

5. 单位、坐标、曲线与路径规范

  • 内部权威单位统一 mm；角度字段明确使用 deg 或 rad。
  • 导入时保留 sourceUnit、viewBox、physicalSize、transformMatrix 和换算证据。
  • SVG 的 Y 轴方向差异在 adapter 统一处理；坐标原点、轴向、左右手系和精度固定。
  • 嵌套 transform 必须按规范合并并有测试覆盖平移、缩放、旋转。
  • 工程几何保留 Line、Arc、QuadraticBezier、CubicBezier；显示或不支持曲线的格式才离散。
  • 曲线离散设置 chordError、最大段长和最大细分次数；达到上限仍超差则失败。
  • 不是所有路径都必须闭合；外轮廓、孔洞、开口切缝分别检查。
  • Cut、Crease、Perforation、Slot、GlueArea、PrintArea、Bleed 语义分离，不能只靠颜色猜测。

6. 材料工艺配置与补偿

新增版本化 MaterialProfile 和 ProcessProfile，材料物性与加工工艺分开管理。

配置组字段示例要求
材料materialId、boardType、measuredThicknessMm、fluteType、grainDirection标称厚度不等于实测厚度；记录测量方式和批次。
折叠/压痕creaseRuleId、channel、allowance、foldDirection按材料、厚度和设备校准。
切割cutProcess、kerfProfile、toolOffset模切、打样刀、激光分别配置。
装配tabClearance、lockClearance、glueWidth、assemblyTolerance与具体结构共同验证。
证据calibrationSamples、factoryId、machineId、measuredBy、approvedAt每个参数有来源、版本和适用范围。

缺少生成器所需工艺配置时返回明确错误，不得使用未经校准的默认值。屏幕留白与物理出血分离；不同加工方式不得共用未经验证的 kerf 公式。

7. 几何验证、审批与发布门禁

  1. 输入检查：schema、单位、尺寸域、参数关系、材料兼容。
  2. 几何检查：坐标有限、路径解析、非预期重复线、自交、零长度、轮廓/孔洞语义。
  3. 拓扑检查：面板邻接、折轴、胶合/锁合、多 Part 装配。
  4. 工艺检查：板厚、方向、折叠补偿、刀具/压痕、间隙、胶合。
  5. 导出回读：独立解析导出文件，检查单位、尺寸、图层、实体和曲线误差。
  6. 实物打样：真实材料、设备、装配、尺寸测量、缺陷记录和工程师审核。

8. 校样与工程导出

格式校样能力工程要求
SVG可排版、标注和缩放明确物理 width/height、viewBox、图层语义和 1:1 映射。
DXF交换预览明确 INSUNITS、坐标比例、图层、实体类型和曲线处理；独立 CAD 回读。
PDF页面排版、注释明确实际打印比例、拼版方式；禁止静默 Fit to Page。

导出任务引用 immutable GeometryDocument ID + hash + exporter version + config hash。文件生成后再次解析回读，记录尺寸、实体、单位、曲线误差和文件 SHA-256。校样文件不得通过更改标签就变成工程文件。

12. 测试矩阵与验收标准

  • 单位：mm/inch/pt/px、SVG viewBox、嵌套 transform、旋转缩放后的基准长度。
  • 参数：最小/最大/越界/零/负/缺失/非数值、dimensionBasis。
  • 几何：零长度、重复线、自交、开口切缝、孔洞、圆弧、Bezier、极端曲率。
  • 结构：面板邻接、折轴、锁舌/插舌、胶口、多 Part 装配。
  • 工艺：厚度、方向、不同加工方式、缺失或未批准 profile。
  • 导出：SVG/DXF/PDF 物理尺寸、图层、实体、曲线误差、独立回读。
  • 审批：几何失败、单位未知、版本不存在、参数超域、材料未批准、hash 不一致必须拒绝。
  • 版本：旧订单不随代码升级改变；新规则必须形成新版本。
验收项通过标准
输入一致性实际参数与用户确认值一致，不静默夹取或替换。
确定性同版本、同输入、同 profile 产生相同 canonical geometry hash。
物理比例已知基准长度经独立软件回读符合设定容差。
验证一致性ValidationRun、Approval、ExportArtifact 绑定同一 hash。
审批拒绝任一 required check 未通过都不能发布 qualified。
实物验证真实材料、设备、工艺、实测数据、缺陷记录和审核人齐全。

测试状态只使用 Passed / Failed / Blocked / Not Run / Not Applicable。没有运行证据不得写 Passed；软件测试通过不代表生产验证通过。

13. 兼容迁移与风险控制

  1. 先加新 schema 和字段，不立即删除旧字段。
  2. 旧资产只读保留；转换结果生成新 GeometryDocument，并记录 sourceArtifactId。
  3. 单位未知、曲线不支持、语义缺失的资产标记 legacy_preview_only。
  4. 新导出通过 feature flag 灰度启用；旧校样流程继续可用。
  5. 旧审批记录只读保留，不自动升级为新标准下 qualified。
  6. 数据库迁移可回滚；文件转换分批执行并记录失败项。
  7. 回归和独立回读完成后，再关闭旧生产导出入口。

14. 交给 Cursor / Codex 的开发执行总提示词

你是 BOXCRAFT 项目的资深包装 CAD、几何内核和全栈工程师。
你必须基于当前本地仓库代码工作，不要重新拉取 GitHub，也不要假设旧报告与当前代码完全一致。

项目技术栈：
- Vue 3 + TypeScript
- Django REST Framework
- 现有 Node Geometry Service，复用 TypeScript 几何模块
- Docker Compose + Caddy

工程规则：
- 内部权威单位 mm，导入源单位和换算证据必须保留。

- Cut、Crease、Perforation、Slot、GlueArea、PrintArea、Bleed 语义分离。
- 多坯件装配关系不得强塞进单一折叠树。
- 材料厚度、折叠补偿、压痕、kerf、间隙必须来自有版本的 MaterialProfile/ProcessProfile。

15. 最终技术决策

推荐路线：自研 Geometry Core 为唯一权威计算核心；Pacdora/Packative 作为来源明确的资产适配器与研究参考；多个独立盒型生成器共享 GeometryDocument；材料工艺配置独立版本化；验证、审批、导出绑定同一几何哈希；实物打样限定生产适用域。

第一阶段只做可信链路，不追求模板数量。建议以 FEFCO 0201 为首个限定材料、设备、尺寸范围的实物验证闭环，然后扩展插舌盒、邮寄盒和锁底盒。
