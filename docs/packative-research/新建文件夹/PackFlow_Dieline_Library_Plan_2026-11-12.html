本方案新增一条独立的“素材库建设”路线：通过允许的在线批量采集、自有/供应商文件批量导入和后续自有引擎预生成，把真实、固定规格的刀版变成可检索、可预览、按权限下载的资产。素材库不等待参数化算法逆向完成，也不替代原有算法研究。

本次交付为方案、开发提示词和数据契约示例；未执行 Packative 批量采集，未新建实际素材数据库，未交付第三方刀版文件。文中的数量、预算与性能指标是建议验收目标，不是已取得成果。

01｜执行结论与产品定位

之前的专项方案主要解决“为什么某个尺寸会产生这样的刀版，以及如何独立计算”。用户现在补充了另一项明确需求：“我也要一个现成刀版素材库”。两者应并行，而不是用算法研究替代素材积累。

本方案的第一优先级是：用户打开素材库，找到一个已经存在的盒型与固定规格，查看真实刀版，确认限制后下载对应文件，或作为新设计的起点。

路线 本轮目标 核心成果 是否必须先恢复计算公式
A. 现成刀版素材库 将可用固定规格集中管理 文件、尺寸、分类、预览、授权、下载与版本 不需要
B. 参数化刀版研究 识别参数如何决定几何 样本、候选规则、独立生成器与测试 需要研究并验证
C. 自有生成器预生成 把成熟规则输出为常用规格 可追溯的固定规格资产 依赖已验证的自有规则

建议实施顺序：先打通 A 的小规模真实闭环，B 继续独立研究，C 在规则成熟后接入。 A 与 B 共用经过授权的原始证据和标准化几何，但分别管理发布权限、研究用途与生产验证。

02｜问题、目标用户与成功标准

2.1 已知需求与默认假设

**已知需求：**需要现成刀版素材库；参考对象包括 Packative Studio；已有本地 PackFlow 项目；沿用 Vue3 + TypeScript、Django REST Framework、Docker Compose；Caddy 直接托管 Vue 构建产物并反向代理后端，不增加长期运行的独立前端容器；不破坏现有包装、装箱、卡板和物流功能。

**默认假设：**第一版以内部资料管理员、结构设计/工程人员为主要用户，同时预留面向客户的目录和下载权限。用户没有确认公开销售素材，因此本方案不默认公开全部资产，也不加入收费商城。

**待确认但不阻塞基础开发：**已有文件数量与权属、Packative 当前采集许可、素材库是否最终向外部客户开放、现有对象存储和任务队列的实际配置。开发者先读本地代码核实，不依据历史描述擅自改架构。

2.2 三类用户任务

用户 任务 验收结果
资料管理员 批量导入、补资料、处理重复、审核发布 原始文件可追溯，错误和许可缺口可定位
设计/工程人员 按盒型、规格、材料、验证状态找刀版 能找到正确版本并下载；看清尺寸定义与适用限制
客户用户（后续开放） 浏览获准公开的素材并下载/创建设计 看不到内部、其他客户或未授权文件

2.3 指标口径

主指标为“授权与技术审核均通过、可按指定用途下载的独立固定规格资产数”，不统计单纯的文件个数。

一个盒型的一个规格包含 SVG、EPS、PDF 三个格式，只计一个资产；同一资产的历史修订不重复计数。天地盖等多部件结构作为一个资产包，其底盒、盖盒分别记录为部件。

第一轮建议以 5 个结构家族 × 每类约 10 个固定规格 = 约 50 个合格资产作为试点目标。它不是对 Packative 可访问盒型数量、授权范围或既有库存的声明；资料不足时如实降低实际数，不制造文件凑数。

其他验收目标：已发布资产来源记录覆盖率 100%；下载权限检查覆盖率 100%；重复任务不重复创建同一修订；测试集中的登录页伪文件、未知单位、受限文件全部被正确拦截；导入失败有明确原因且可重试。

03｜素材库收什么，不收什么

3.1 资产种类必须分开

种类 用户能做什么 不能默认做什么
固定规格刀版 查看某一具体规格、下载已有格式、按权限创建设计副本 输入新尺寸自动得到正确结构
参数化模板 在明确范围内改变尺寸，由已验证引擎重算 无范围限制地任意变形
参考图片 看结构或外观参考 当作可生产矢量或可编辑 CAD
多部件刀版包 一次取得盖、底、内托等关联部件 拆开后仍隐去配套版本和配合尺寸

“可编辑矢量”不等于“可参数化”；改变图片/SVG显示比例不等于改变成品规格。 对固定规格资产，界面只允许选择已存在规格；未命中的尺寸进入“申请补充/自有引擎生成”，不能悄悄拉伸原图。

3.2 文件格式策略

原始文件保持不变；派生文件另存版本、转换器版本、参数、校验报告和父文件关系。

格式 第一版处理方式 对用户的说明
SVG 优先实现安全解析、切压线显示、坐标和单位校验 只有通过解析的文件才显示可用图层和尺寸
DXF 保存原件；按实际解析器支持范围预览与校验 单位未知或实体不支持时显示限制，不强行转换
矢量 PDF 保存原件并生成参考预览；具体提取能力单独验证 PDF 后缀不保证内容是矢量，也不保证可生产
EPS 原件隔离保存；有安全转换能力时生成派生预览 转换成功不自动升级生产状态
AI 保存且标为解析能力待确认；只有已验证的兼容文件才生成预览 不承诺所有 Illustrator 文件自动解析
PNG/JPG 作为参考图或缩略图 不纳入可下载刀版的合格数

第一版不承诺任意格式互转，不把位图包进 PDF 冒充矢量，不自动抹去版权标记或客户标识。包含客户图案的原件先判定保密与用途；如需提取纯结构，必须有相应处理权限并生成可追溯派生版本。

04｜素材从哪里来

4.1 多来源建设，不把 Packative 当成唯一供应链

来源 建议使用方式 进入公开下载区前的条件
自有设计及历史项目 本地目录/压缩包 + 清单批量导入 核实权属、客户保密、图案和结构的使用范围
合作纸箱厂、刀模厂 约定格式，接收批量交付包 明确保存、修改、商业使用、展示和再分发权限
Packative 等商业平台 对允许的盒型/尺寸做目录化批量采集或官方导出 确认允许自动取得及目标用途，不把登录权限等同再分发许可
明确许可的第三方资源 按具体文件的许可入库 保留许可文本、署名及范围；网站宣传词不能替代文件许可
自有参数化引擎 预生成常用规格 记录引擎/规则版本与验证范围，按技术审核发布

Packative 官方页面描述了真实刀版、自定义尺寸和生产导出能力，说明其输出可作为研究和业务对接的候选对象；页面对“用户创建设计”的归属说明，不能单凭这一句话推定基础模板、批量采集和公开分发的授权范围。S1

EngView 官方介绍了可检索的参数化包装模板库，可作为商业合作/采购候选，不在本方案中默认其模板可免费下载、转售或批量再分发。S2

FEFCO 编码可作为瓦楞包装结构分类的参考。其网站条款对内容用途、修改和再发布另有约束，因此不能直接将代码手册插图打包成可售素材库；结构编号匹配也必须人工复核，不按外观相似自动贴标准号。S3S4

4.2 Packative 的当前证据边界

上一版方案记录了本地研究中的 SVG/EPS、接口线索及部分访问限制，但本次没有重新登录或复测这些接口。公开检索可以取得官方产品介绍；本次直接读取 conditions 和 robots.txt 未成功，因此不声称已确认当前有效的批量采集许可或已取消访问限制。

计划中保留 Packative 适配器，但默认 enabled=false，在访问与用途证据齐全后才启用。这不妨碍开发采集器、导入器、数据库和网站，也不妨碍先用自有及已授权素材完成真实闭环。

05｜在线批量采集方案

5.1 采集的基本单位

采集任务不是“不断翻页下载文件”，而是一条明确的规格记录：

来源 + 来源模板标识/修订 + 长宽高 + 尺寸定义
+ 材料/可见工艺选项 + 需要的格式 + 授权上下文

只有来源公开目录、实际交互或许可交付清单中真实出现的模板和下载资源可进入队列。不拼接未知 UUID，不枚举 CDN 路径，不改变租户/用户标识扩大访问。

5.2 REA 与批量采集器各做什么

**REA 做入口和契约研究：**确认可访问目录、盒型名称、输入字段、规格选项、材料选项、下载按钮、生成状态、真实下载方式、错误提示；记录证据和当前工具版本。不能把历史 API 路径写成已确认公开接口。

**确定性采集器做执行：**按人工审核的规格清单逐条填写、等待、下载、计算哈希、保存元数据、记录失败、恢复任务。优先使用允许的官方批量导出/API；没有时才使用允许的浏览器交互，不让 LLM 每个文件临时猜按钮。

Playwright 官方支持等待页面下载事件和保存文件，同时说明浏览器上下文关闭后临时下载会被删除。因此实现必须等待下载完成并显式保存到受控持久目录，而不是只记录临时路径。S5

5.3 推荐流水线

审核来源与用途范围
→ 获取实际盒型目录和字段映射
→ 建立待采规格清单
→ Dry-run：显示任务数量、成本和限制
→ 小批试运行并检查真实文件
→ 正式队列：填写/生成/下载
→ 校验身份、格式、文件大小与哈希
→ 原件隔离归档
→ 安全解析与标准化
→ 几何/资料检查
→ 权限审核和人工确认
→ 发布素材库

5.4 常用规格怎么选

素材库路线按“业务覆盖率”采样，算法研究路线按“控制变量和区分候选公式”采样。两者可共享样本，但不要混淆目的。

优先次序：实际历史订单中出现的规格 → 供应商常备规格 → 平台真实预设规格 → 经有效范围验证的小/中/大及长条/扁平/高盒规格。

例如 100×80×50、150×100×60、200×150×100 mm 可以作为待检查的候选点，不是已验证的 Packative 通用有效尺寸，也不是本次提供的现成刀版。必须按盒型检查关系约束、尺寸口径和可选材料后才能入队。

不做 L/W/H 全排列穷举，不为了凑数量把同一 SVG 改名或缩放生成几十条。首批 10 个任务确认下载与解析准确后，再扩展到约 50 个合格规格。

5.5 任务控制与停止条件

默认建议每来源 1 个执行并发、任务间隔至少 10 秒作为初始工程配置，服从站点更严格限制；这些值不是许可，也不保证站点接受。每轮设置任务、请求、字节和费用预算，浏览器导航及实际相关请求均计入日志。

情况 处理
网络短暂超时或 5xx 有界退避，最多重试 2 次；记录每次尝试
登录过期或 401 暂停，等待有权账号重新建立本地会话
403、验证码、权限提示 停止该来源，不通过换 IP、换账号或隐藏接口绕过
429 按来源要求和 Retry-After 暂停，不在同一轮循环冲击
下载收费、消耗额度、提交订单 默认不执行，必须有明确预算/业务授权
下载文件是 HTML/空文件/错误 JSON 失败并留诊断，不作为刀版入库
已完成的任务 复用完成记录，不重复请求和生成费用

任务状态建议：pending → running → acquired → validating → review_required → completed；异常分支为 failed / paused / blocked / cancelled。区分取得文件与发布素材，不以 HTTP 200 或下载事件本身作为成功标准。

06｜本地与供应商批量导入

在线采集不是唯一入口。本地历史文件、供应商交付包和未来自有引擎均走相同入库管线，避免网站采集受阻时素材库完全停摆。

批量导入支持“目录 + JSONL 清单”或受控 ZIP。清单映射资产、部件、规格、文件路径和来源许可；文件名只用于候选识别，不直接作为可靠尺寸证据。扫描先输出 dry-run 差异报告，再创建导入任务。

ZIP 防止路径穿越、软链接逃逸、文件覆盖、解压炸弹；限制解压后总大小和文件数。文件先隔离存储，再处理，不能直接落在 Caddy 公开目录。上传文件需要类型校验、权限控制、大小限制、非公开存储及解析隔离，这与 OWASP 的文件上传防护原则一致。S6

导入完成报告列出：实际扫描文件数、真实资产数、重复数、待补资料数、损坏数、权限受限数、技术审核通过数与发布数。空文件、示例和测试夹具不能纳入真实库存。

07｜数据模型与文件结构

7.1 数据层级

结构家族 Family
  └─ 来源模板 Template（含来源模板版本/结构变体）
      └─ 固定规格 AssetVariant
          └─ 不可变修订 AssetRevision
              ├─ 部件 Parts（盖/底/托/独立纸片）
              ├─ 文件 Files（原件/派生件/预览）
              ├─ 技术校验 Validation
              └─ 授权与来源证据 Evidence / Grants

同一几何可对应不同来源和许可。底层二进制可以去重，但不能因为某来源允许公开，就自动把另一份受限记录视为公开；授权必须绑定来源及具体资产/修订范围。

7.2 必要字段

分组 建议字段 规则
标识与分类 asset_id、family_id、source_template_id、template_revision、titles.zh/ko、tags、standard_code 源名称和中文/韩文译名分别保存；标准号可为空
成品尺寸 length_mm、width_mm、height_mm、dimension_basis、dimension_evidence 不确定时为 null/unknown，不随意交换 L/W 或把展开宽高当成成品尺寸
材料与工艺 material、thickness_mm、grain_or_flute_direction、clearance、visible_options 未提供不写 0，也不由某段偏移反推纸厚后标为事实
几何 unit_status、cut/fold/other_counts、physical_bbox、parts、topology_status 解析值与推断值分层，单位未确认不能发布为可生产
文件 format、role、bytes、sha256、storage_key、parent_file_id、converter_version 原件不可变；不存临时签名 URL 作为持久身份
来源 source_id、source_url_redacted、source_record_id、captured_at、source_modified_at 来源时间、采集时间、审核时间分开
用途 grant_id、rights_scope、confidentiality、attribution、valid_until 下载、修改、公开展示、再分发分别判定
质量 ingest_status、technical_status、manufacturing_status、reviewer、reviewed_at 技术通过不自动改变授权或打样状态
算法关联 research_sample_id、generator_id、generator_version、input_snapshot 没有生成器的固定刀版不能标可参数化

7.3 数据库实体建议

沿用现有用户/组织/项目系统，新模块至少包括 DielineFamily、SourceTemplate、AssetVariant、AssetRevision、AssetPart、AssetFile、SourceProvider、UsageGrant、AcquisitionJob/Item、ValidationReport、PublicationDecision。收藏与项目引用尽量复用现有能力。

先确认现有数据库与对象存储再实现。默认建议使用 PostgreSQL 保存结构化元数据，文件放私有对象存储或受控本地卷；不把大体积 SVG/base64、整个 HAR 塞进业务表。

7.4 文件布局建议

dieline-library/
  originals/<source-id>/<revision-id>/<file-id>.<ext>
  derivatives/<revision-id>/<pipeline-version>/<file-id>.<ext>
  previews/<revision-id>/<preview-version>/thumbnail.webp
  metadata/<revision-id>/manifest.json
  reports/<revision-id>/validation.json
  evidence/<source-id>/<evidence-id>.json
  exports/<job-id>/bundle.zip

以上是私有存储键示意，不是公开 URL。原件、证据和临时导出包不暴露静态目录索引。导出包只包含当前用户获准取得的文件及许可说明，不附带 Cookie、访问令牌、私有合同或不应公开的源站凭据。

08｜去重、标准化与质量分级

8.1 三层去重

**文件去重：**SHA-256 相同则共用存储，但保留各来源记录与权限。

**任务幂等：**来源、模板版本、输入参数、材料/工艺选项、格式和用途上下文形成任务键。未知字段保留未知；不能因缺失值相同就误合并不同结构。

**几何相似：**在已知物理单位下比较切线、压线、部件和结构。可把平移/允许的旋转用于比较，但不能把不同尺寸统一缩放后认定为同一规格，也不能把镜像自动视为相同。缩略图相似只用于提出人工复核候选。

8.2 几何解析准则

SVG 解析必须正确处理 viewBox、嵌套 transform、相对/绝对路径、曲线和坐标轴方向。W3C 明确这些机制会改变用户坐标与视口的映射，不能简单把坐标值当作毫米。S7

优先使用明确的图层/语义属性识别 cut/fold；颜色映射需来源规则和人工验证，无法判定的线条保留 unknown。PDF 页面边界、EPS BoundingBox、图片像素尺寸分别记录，不等同真实切割轮廓。

不得为了“修复”自动闭合所有路径：不同盒型可能有开口、槽、孔、独立部件。检查应针对结构角色，包括重复路径、异常零长线、交叉、部件缺失、曲线误差和尺度错误。复杂或不支持实体进入人工复核。

8.3 三个独立状态轴

状态轴 示例 含义
取得/解析状态 acquired / parsed / failed / needs_metadata 文件是否拿到、能否解释
使用权限状态 unknown / internal_only / public_preview / redistributable / revoked 谁可以用、如何用
制造验证状态 reference_only / engineering_reviewed / sampled / production_validated 到哪一级工艺验证

“已打样”必须绑定具体修订、材料、厚度、工艺及记录；不能将某尺寸打样结论传播到全家族。第一版素材即使可下载，也应显示尚未打样的提醒，不使用“一定可量产”的承诺。

8.4 发布门槛

可预览的参考资料可以保留缺失参数，但必须显示“参考资料”；进入“可下载固定规格刀版”分区至少要求：文件有效、原始来源可追溯、用途许可明确、成品尺寸口径已确认、物理单位已校准、主要切压线或相应限制已审核、文件版本锁定。

权限审核与技术审核独立。文件技术上完美但用途不明，仍不能公开下载；有再分发许可但几何损坏，也不能标为合格素材。

09｜前台页面与用户操作

9.1 目录页

展示卡片或列表，优先呈现结构缩略图、盒型、成品长宽高、内/外尺寸、材料、格式、固定/参数化标记、许可与验证等级。默认排序按业务相关度及审核质量，不以文件数量制造繁荣。

筛选支持中文/韩文名称、类别、尺寸范围、材料、格式、内部/外部用途、是否有完整多部件、是否已打样。仅对有权访问的记录做查询与计数，避免通过总数或筛选项泄露其他客户资产。

9.2 详情页

提供大图、切线/压线分层开关、部件切换、真实尺寸与单位、可下载格式、修订历史、授权说明、材料/工艺注意事项、关联项目与算法模板。未知字段显示“未确认”，不隐藏。

对固定规格显示“此文件规格固定；修改尺寸需重新生成/设计”。若对应自有引擎通过验证，另提供“使用参数化模板”入口，生成新资产或设计副本，不覆盖原件。

9.3 搜索与尺寸推荐

第一版做精确规格和范围筛选，近似结果明确标记“仅相近规格，不保证装得下”。成品内尺寸未知或方向未确认时不提供自动适配结论；不要对 L/W/H 排序后直接认定可互换，插口和展示方向可能有业务差异。

9.4 下载与设计引用

用户选择格式后，后端重新检查资产、修订、用途和用户权限，再返回文件流或短期签名链接。批量 ZIP 需要生成清单、记录修订与文件校验和，并仅包含当次授权文件。

“加入设计”创建用户自己的副本，关联固定的资产修订和文件哈希；原素材更新不能悄悄改变历史订单或设计。第一版不承诺从任意固定刀版自动恢复 3D 折叠；只有存在可靠面板/折叠数据时才开放 3D。

10｜管理后台与权限模型

后台需要来源管理、任务列表、规格计划、批量导入、重复候选、待补资料、预览/转换状态、授权审核、技术审核、发布/下架、导出与审计日志。避免第一版加入与当前任务无关的大型仪表盘。

建议角色：资料管理员管理来源和任务；审核员管理质量/用途审核；内部使用者下载内部许可范围内资产；客户用户只访问明确发布给该客户或公开的资产。权限由后端强制执行，不靠前端隐藏按钮。

许可至少拆分为 can_collect_automatically、can_store、can_transform、can_use_internally、can_use_commercially、can_show_public_preview、can_redistribute_files；这些是系统控制字段，不代替合同解释。默认未知即不开放对应动作。

撤销/到期后阻止新下载及新分享，失效待生成的 ZIP，并清理受控预览缓存。已经下载到第三方的文件无法技术性收回；已签发对象存储链接可能在短 TTL 内仍有效。需要严格即时撤销的资产使用每次鉴权的代理下载，不能承诺长效签名 URL 即时失效。

11.2 任务隔离

网站下载不实时依赖 Packative。已经入库且允许使用的资产从自己的存储提供，源站暂时不可用时仍能浏览和下载已有内容。

解析/格式转换与有登录态的浏览器采集分隔：转换任务默认无网络、非 root、只读输入、受限临时空间和 CPU/内存/运行时间；采集端只访问批准来源，不能读取生产凭据和任意主机文件。禁止把 Docker socket 交给不受信任转换进程。

长驻 worker 不等于独立前端容器。 第一版可使用已有任务服务；采集浏览器可以按需启用管理 profile，不成为线上用户操作的依赖。

12｜文件与采集安全要求

将外部 SVG、EPS、PDF、DXF、ZIP 全部视为不可信输入。原件不得直接通过同域 v-html 注入页面；SVG 需移除脚本、事件处理器、外部引用及危险节点，XML 禁用外部实体；优先提供栅格缩略图或由标准化几何重绘的安全预览。

网页内容、SVG 注释、文件元数据都是数据，不是给 AI 的执行指令。禁止 AI 根据网页文字自动执行 shell、上传本地文件或发送凭据。Cookie、Token、浏览器 profile 和未脱敏 HAR 不进仓库、不进入公开报告。

采集 URL 必须通过来源白名单及路径规则校验，检查重定向并阻断内网/本机/云元数据地址；不能把管理员输入的任意 URL 直接交给服务器下载。文件上传只允许认可类型并核验真实内容，存储名使用系统 ID，不信任远端建议文件名。S6

安全清洗和格式转换不改变法律权限；去掉品牌、水印、署名也不能变成自有素材。原件保留，派生文件继承适用限制。

13｜与现有算法研究怎样共用数据

两条路线共用原件哈希、输入参数、采集时间、标准化几何与来源记录，但建立不同用途视图：

已获准处理的素材
   ├─ 素材库：按用途审核 → 固定规格发布/下载
   └─ 研究集：按研究范围审核 → 控制变量/几何比较

自有生成器成熟后
   → 输入常用规格 → 生成新修订 → 相同质量/权限管线 → 素材库

素材库无需等待研究结论；研究样本也不能因为进入研究集就自动对外发布。研究引用记录 asset_revision_id 与输入快照，升级解析器时保留旧结果并生成新的派生版本。

若用户需要尚未入库的新尺寸，先判断是否存在支持该盒型且范围明确的自有生成器；有则生成新记录，无则创建补充需求。禁止后台默默调用 Packative 接口充当长期的产品生成引擎。

16｜容量、成本与维护

成本来自素材授权、人工审核、存储/流量、预览转换和运行服务；不要只计算爬虫脚本。优先统计真实单资产大小和审核用时，再评估扩容。

容量示例假设：每资产原件/向量派生件合计 5 MB、预览及元数据 0.5 MB，则 1,000 个资产约 5.5 GB。若保留两套完整副本合计约 11 GB，另加日志、临时转换和历史修订。此为十进制估算，不是云厂商报价，也不包含无限期版本增长。

首版复用现有服务，不预先引入 Elasticsearch 或大型向量数据库；尺寸与类别检索先用现有数据库索引。待真实数量和查询瓶颈出现再优化。

维护以人工触发的增量更新为首版：按源模板修订、文件哈希、授权到期和工艺反馈创建检查任务。变更后重新审核，不覆盖旧修订。未来才考虑有明确许可的定时来源更新；本次没有创建任何后台自动任务。

备份要覆盖数据库、对象文件、许可证据和配置；浏览器登录态与密钥单独保管，不放素材备份给客户。至少执行一次真实恢复演练，不能只检查备份文件存在。

第一版不做公开素材交易市场、收费订阅、全站无限抓取、全尺寸穷举、任意文件自动转 3D、全量恢复 Packative 算法、所有 AI 文件解析、自动工程认证或自动投产。

# 刀版素材库——独立验收提示词

作为独立QA审查当前本地实现，不信任开发报告中的完成声明。只读检查后先制定测试清单，再运行可用的真实测试；需要修复时保持最小增量，不覆盖用户改动，不拉取仓库，不执行生产部署或破坏性迁移。

第一步：核对范围和约束
确认固定规格素材库独立于参数化引擎；Vue3/TypeScript、Django DRF、Caddy直接托管dist、不存在新增长期前端Web容器；检查是否破坏现有刀版、装箱、卡板、物流、登录。

第二步：数据真实性
统计独立资产、修订、格式、部件、示例与实际来源。三个格式不能算三条资产，fixtures不能算真实采集。抽样核对原件存在与SHA-256、来源/时间、参数对应、文件内容与声明格式、尺寸定义、授权证据。检查有无HTML登录页、空文件、同一SVG改名冒充多个尺寸。

第三步：权限与保密
覆盖未登录、内部用户、客户A/客户B、管理员；测试目录计数、详情、缩略图、单下载、批量ZIP、导出领取。权限必须后端强制，不能只隐藏按钮。同哈希多来源不能串许可。授权到期/撤销后新请求拒绝，旧URL有效边界与方案一致；不能声称回收已下载文件。

第四步：文件与几何
测试未知单位、inch/mm、嵌套transform、曲线、开放切线、重复/退化路径、多部件、未知DXF实体、位图PDF、不兼容AI。检查是否乱闭合、乱缩放、从像素猜毫米、从0.5mm偏移猜纸厚。转换损坏要失败或降级，不可宣布生产通过。

第五步：安全与任务
使用无害测试夹具验证活动SVG/外链/XML实体不被执行、ZIP路径穿越与解压超额被拒、任意URL及内网重定向被挡、令牌不入日志、转换进程权限隔离。测试任务中断/重启/幂等、401/403/429/验证码停止，不用真实绕过措施。

第六步：功能与版本
真实导入 → 安全预览 → 补资料 → 技术/用途审核 → 下载 → 原件哈希核对；固定规格改尺寸不允许拉伸伪装，新版本不改变旧项目；源站断网时已入库允许素材仍可用；执行一次备份恢复并核对引用和文件。

第七步：输出
测试环境、实际命令、案例、证据、失败/修复/复测、未运行项、真实素材数量、公开可用数量、制造验证数量分别报告。合成测试与真实来源测试分开。缺少浏览器、凭据、授权或原件要说明，不能填通过。

结论用：可内部试用 / 有条件可发布 / 不可发布，并逐项给阻断原因。不能仅凭截图宣布功能完成，也不能把技术验收等同制造工艺认证。
