2. 现有三条引擎路径的真实定位

路径实际实现当前能力判断建议定位
PacdorapacdoraGeomKnife.js 读取已有 geometry JSON，转换为面片、刀线、折线和动画数据；样本使用 locked-sample 语义。固定规格样本适配/回放；不能据此认定已拥有 Pacdora 原生参数化算法。外部资产适配、研究参考、对照测试。
自研src/knife.js 与模板注册表计算尺寸、面板、刀线、折线；Node 服务复用同一套模块。最接近可持续扩展的自有参数化核心，但仍有示意补偿、回退和验证边界问题。BOXCRAFT 正式计算主干。
Packative 主适配器packativeGeomKnife.js 解析已有 SVG Cutting/Creasing，转为二维刀版；部分样本锁定尺寸。静态 SVG 几何导入，不等于完整复现 Packative 参数化引擎。只读资产、单位/路径适配、结构对照。
Packative 研究原型研究目录有 crashlock 生成逻辑，如 generateCrashlockWithOutline()，拆分盒身、锁底和顶盖轮廓。特定结构的参数化研究原型，不等于通用引擎或生产级。候选盒型生成器来源，逐项验证后并入自研。
判断：目前不是三套成熟引擎在竞争，而是“一套自研基础 + 两种外部资产适配路径 + 一个局部参数化研究原型”。固定样本回放不能称为任意尺寸生成。

3. 关键源码风险与整改要求

3.1 Packative SVG 单位归一化

研究资料保留了候选比例 25.4/96，样本坐标也可观察到 SVG user unit 与毫米之间的关系。但主适配器存在把原始坐标直接标记为 mm 的风险路径。若不先处理 viewBox、width/height、单位与 transform，DXF 可能把 user unit 当作毫米。

P0 修复：导入时记录 sourceUnit、viewBox、physicalWidth/Height、transform chain、mmPerUnit 和换算证据。单位未知或比例冲突时允许预览，不允许工程导出。不得对所有 SVG 无条件套用 96 DPI 比例。

3.2 验证与导出参数不一致

Node Geometry Service 的验证调用和导出调用传入的参数集合不完全相同；导出侧可能额外使用 advanced params、materialId、fluteDirection。风险是检查一组参数、输出另一组参数。

整改：完整参数归一化后只生成一次不可变 GeometryDocument；验证、审批、哈希和导出均消费同一对象。

3.3 制造审批未强制几何验证

后端 evaluate_manufacturing_gate() 记录了几何验证结果，但最终 ok 判断存在未强制依赖 validated.ok 的风险。生产 gate 必须强制检查几何通过、单位可信、参数在适用域、材料工艺配置批准、导出器能力匹配及 hash 一致。

3.4 校样与工程导出混淆

现有 SVG/PDF 更偏展示校样：SVG 可能只有 viewBox，PDF 可能按页面缩放；DXF 才明确标记 physical_mm。后端不能仅凭审批快照或近似标记就将导出标为 manufacturing_ready。

校样工程导出
可缩放、排版、加标注，用于沟通和视觉检查。明确物理尺寸、单位、图层语义、几何验证、文件回读、版本和审批证据。

3.5 静默回退和自动夹取

部分路径存在厚度夹取、未知模板默认回退、几何运算失败时使用矩形/AABB 近似等行为。它们可用于实验预览，但生产路径必须对非法输入、未知模板、布尔失败和不支持结构返回明确错误。Node API 已有拒绝未知模板的入口保护，因此问题在于底层和不同入口语义不完全统一。

3.6 曲线精度

适配器中存在 SVG arc 近似和 Bezier 固定段数采样。固定段数不能保证不同尺寸和曲率下误差一致。工程模型应保留 Line/Arc/Bezier，渲染或不支持曲线的导出格式再按 chord error 自适应离散；达到最大细分仍超差应失败。

3.7 样本范围不等于参数域验证

classifySize() 若仅因输入落在样本 min/max 包围范围内就标为 validated，会误把未测试组合当作已验证。应区分：

  • sample_verified：精确样本通过。
  • inferred_candidate：推测范围内但未独立验证。
  • domain_qualified：有验证计划与证据支持的参数域。

3.8 3D 合盖不是碰撞检测

当前折叠模拟使用简化面板/包围盒逻辑，不能证明无穿透。应准确命名为闭合位置示意检查，后续再增加允许接触、胶合、锁合和干涉检查。

3.9 哈希与版本可重现性

若 geometry hash 只包含模板 ID 和部分尺寸，而不包含完整参数、材料工艺配置、生成器版本、曲线和导出配置，就不能证明输出与审批对象一致。旧版本缺失时不应静默回退到 current version。

强制原则：被验证、被审批、被导出的必须是同一个不可变几何文档；审批绑定该文档的 canonical hash。历史订单保留已批准文件，重新计算必须创建新版本并重新审批。

4. 生产级刀版引擎的定义

维度最低要求证据
单位与尺寸内部单位统一 mm，坐标/原点/精度明确，输入不静默变更。单位测试、基准尺寸、文件回读。
几何完整性Cut/Crease/孔洞/开口语义明确，路径按类型检查。几何报告、黄金样本。
结构正确性面板、铰链、胶合、锁合、多件装配关系明确。结构约束测试。
材料工艺板厚、方向、压痕、折叠、间隙、胶合、设备规则有依据。材料工艺配置、打样数据。
文件正确性SVG/DXF/PDF 单位、比例、图层和曲线受控。独立 CAD 回读、1:1 测量。
版本可重现生成器、参数、材料配置、导出器和审批可追溯。不可变快照与哈希。
生产资格限定在模板版本、尺寸域、材料、设备和工艺条件。实物样品、实测和工程审核。
核心认知：生产资格授予“模板版本 × 结构变体 × 尺寸范围 × 材料配置 × 工艺条件 × 导出配置”，不是给整个引擎永久设置 production_ready=true。

5. REA / 爬虫数据的正确用法

继续研究 Packative，但从“抓更多参数”转向“推导并验证具体结构规则”。每个盒型建立证据包：

  • 原始样本只读保存、来源 URL、获取日期和授权依据。
  • 源坐标、viewBox、物理尺寸、单位换算与 transform。
  • 结构特征：面板、胶口、锁舌、插舌、防尘翼、曲线和压痕。
  • 规则假设：哪些量随 L/W/H/T 变化，哪些是常量，哪些存在分段边界。
  • 生成器版本、拟合样本、独立测试样本、失败案例和误差报告。
  • 材料、加工方式、工厂、打样结果和审核结论。

用于推导的样本不能同时称为独立验证样本。测试样本一旦用于修改公式，应移出最终独立测试集。整体外框拟合不能替代锁舌位置、锁底搭接、胶口、折线和装配间隙等结构规则推导。

已有 crashlock 研究原型将盒身、锁底和顶盖拆分，并记录过特定留出样本的结构对照结果（如结构性裁切 61 条、压痕 14 条）。这说明研究原型有价值，不证明材料补偿、所有尺寸组合或真实设备生产已经验证。

获取到文件不等于取得商业复制、再分发或训练使用权。产品发布应使用自有设计、明确授权资料，或基于通用结构原理独立实现并保留来源审查。

7. 决策与实施优先级

路线决策
自研引擎继续投入，作为正式核心。
Pacdora 路径保留适配与对照；不把样本回放当作参数化生产能力。
Packative 路径保留研究成果，逐个结构转化为自有生成器；补齐单位与验证证据。
新增盒型先暂停大规模扩张，修复可信导出链路。
推荐顺序：可信导出链路 → 统一 GeometryDocument → FEFCO 0201 限定条件实物验证 → 插舌盒 → 邮寄盒 → 锁底盒。
