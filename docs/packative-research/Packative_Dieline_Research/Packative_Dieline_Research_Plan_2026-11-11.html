Packative Studio 刀版专项研究方案

版本：V1.0｜研究日期：2026-11-11｜使用环境：Cursor + 已安装的 REA + 当前本地项目

核心目标不是下载一批刀版图片，而是建立一条可追溯的链路：盒型与输入参数 → 真实矢量几何 → 参数变化规律 → 独立计算器 → 未参与推导的样本验收。

本次交付的是研究方案与 AI 执行提示词。已核查官网及仓库中部分原始证据，并对一个 SVG 样本的坐标间距进行算术复核；未登录目标网站重新采集，未完成全部盒型或完整服务端算法恢复。

1. 结论与执行范围

这项工作具备明确的技术起点：你的 docs/packative-research/ 已保存刀版研究、SVG、EPS 文件索引及编辑器响应元数据。下一阶段应从“功能介绍与整体包围盒比较”升级为“路径级解析、同变量差分与规则验证”，不是重新从截图开始。[R1][R2][R3][R4]

目标分为三个可验收层次：

层次 要得到的成果 不能混淆的事情
参数与数据层 盒型目录、输入字段、默认值、范围、材料关联、真实样本与来源 可下载结果不等于已获得全部模板公式
几何与规则层 切线/压线、控制点、面板关系、候选公式、适用范围与误差 拟合吻合不等于恢复原始源码
独立实现层 一个盒型的本地纯函数原型、SVG 输出、独立测试 软件几何一致不等于可直接投产

本轮聚焦刀版；AI 生图、印刷图案、完整 3D 动画和生产报价不纳入主任务。只保留未来联动所需的面板与折线拓扑接口。

建议优先顺序：自动锁底盒（已有证据最丰富）→ 套筒盒（用于检验较简单拓扑）→ 邮寄盒 → 枕形盒 → 其他盒型。这是研究优先级，不是假定所有盒型都采用同一生成器。

2. 本次核查得到的事实与边界

2.1 官方说明支持什么

官网说明 Studio 可以接收长宽高，生成刀版并拒绝部分不能制造的尺寸；同时说明 Studio 与 Packative One 共用刀版服务。[S1]

One 的报价页面区分 Packative CAD、EngView 集成与用户 DXF 导入三类来源；价格页面也区分内置 CAD 与企业版 EngView。因此，不能由某一个样本带有 EngView 风格字段，就推定整个产品的刀版都来自 EngView。[S2][S3]

公开商品页与帮助中心把盒子尺寸描述为内部尺寸。采集时仍需为每个产品和入口保存原始尺寸说明，不能把此结论无条件套用到第三方导入文件。[S4][S5]

REA 官方介绍支持浏览器、脚本及网络证据分析，并明确不保证恢复原始源码或自动克隆应用。执行时应读取本地实际版本、MCP 工具清单和参数模式；不要照抄其他版本的工具名称。[S6]

2.2 你现有仓库已经有什么

本次读取的关键材料：

文件 本次可确认的内容 证据等级
docs/packative-research/README.md 既有研究范围、文件索引、登录与 robots 限制记录 既有研究记载，非本次在线复测
05-参数化刀版几何算法研究.md 多盒型 EPS、SVG、接口与尺寸限制记录，同时明确未恢复完整公式 既有研究记载

evidence/studio-dieline-100_80_80.svg 向量线段、曲线路径、切线/压线属性及坐标变换 本次直接读取原始 SVG 内容

文件记录的事实不自动等同于目标网站今天的行为。需要保留来源文件哈希、采集时间、模板版本以及复核状态。[R1][R2][R3][R4]

2.3 两条已有的刀版链路

现有报告记录了以下接口形态，此处仅作为旧证据线索，不是已验证的公开 API 合约，也没有在本次对其重放请求：[R2]

商品页刀版下载：
GET papi.packative.com/public/online/model
    ?productCode=<已观察到的盒型>
    &length=<L>&width=<W>&height=<H>&format=eps

编辑器刀版服务：
GET <实际观察到的 Studio API origin>/v1/editor/dieline
    ?product=<已观察到的盒型>&length=<L>&width=<W>&height=<H>

旧报告还记录编辑器请求涉及租户与用户上下文。不能从旧报告复制凭据，也不能通过改租户、用户或设计标识来扩大访问范围。程序只记录字段名，认证值放在本机私有会话中。

元数据中真实存在 original_svg_url、original_dieline_url、dieline_url、area_mask_url、main_mask_url、total_mask_url，以及 original_width、canvas_width、bbox_length、version 等字段。[R3]

建议取证优先级：真实 SVG → 其他向量文件 → 元数据 → 图片与截图。 蒙版用于定位设计区域，不能自动替代精确切线或压线。

3. 已发现的具体几何线索

3.1 切线与压线不需要靠颜色猜

样本 SVG 中有：

<line ... ev-style="Cutting" ... />
<line ... ev-style="Creasing" ... />
<g transform="translate(-69.1504,864.108) scale(1,-1)">

该样本应优先按语义字段分类，颜色只作为交叉检查。还必须先处理坐标平移与 Y 轴翻转。SVG 的 viewBox、父级变换和用户坐标会影响几何解释，不能把原始坐标直接当毫米。[R4][S7]

3.2 一个可复核的数值发现

对于保存的 100 × 80 × 80 样本，直接从 SVG 可读到以下坐标差。本表使用 25.4/96 mm 每用户单位的候选比例计算；这不是对所有 SVG 的默认规则。该比例与 CSS 绝对单位关系相符，但真实工程比例仍需跨尺寸、元数据和另一向量出口交叉校准。[R3][R4][S8]

原始坐标差 用户单位 候选换算结果
492.458 − 114.505 377.953 100.00006 mm
794.820 − 492.458 302.362 79.99995 mm
1172.770 − 794.820 377.950 99.99927 mm
1473.240 − 1172.770 300.470 79.49935 mm
520.171 − 219.699 300.472 79.49988 mm

这支持一个值得验证的假设：某些主体线段间距跟随名义长宽，另一些位置存在约 0.5 mm 的偏移。

目前不能说“已发现纸厚是 0.5 mm”或“全部盒型采用固定减 0.5 mm”。 此差值也可能对应模板默认参数、特定结构让位、面板定义或其他补偿，必须用其他尺寸和可独立控制的材料条件验证。

3.3 旧结论中应纠正的推断方式

  • 相同 Cutting/Creasing 元素数量，只证明数量一致；不证明几何邻接关系和折叠拓扑一致。
  • EPS 的 BoundingBox 是文件输出边界的线索，不能不经路径解析就当作真实切割外轮廓；标题、标注、边距和笔画都可能造成差异。
  • 导出头出现 poppler pdftops 不能单独证明几何计算在哪里完成，只能作为输出处理链路的线索。
  • CDN 403 不足以证明“未缓存”；应记录访问失败，不能猜测缓存原因，更不能更换路径或身份继续尝试。
  • 浏览器调整尺寸没有新请求，也不能单独证明纯前端计算；必须排除已加载模板、缓存和延迟请求。
  • 元数据内的 timestamp 是源数据字段，不可当作采集时间；另设 captured_at 和 reviewed_at。

上述是本方案的证据判断规则，不是对目标网站内部实现的断言。

4. REA 专项研究路线

4.1 先建立访问和数据用途清单

既有研究记录 robots.txt 限制 /editor/ 等路径；本次未成功重新取得实时 robots 内容，不应把它视为已取消限制。[R1]

官网可检索到的条款含未经允许再利用及商业使用的限制；同时新闻目录有 2026-10-10 生效的更新公告，而可读条款正文显示较早日期。营销页关于生成设计归属的说明也不能直接解决模板数据的复用范围。执行前需要核实当前有效条款、账号合同与必要许可，不在此作最终法律结论。[S9][S10][S11]

默认执行策略：

已确认有权处理的本地证据 → 离线研究
允许自动采集且用途明确的数据 → 小范围、白名单、可暂停采集
访问或用途不明确的数据 → 不新增采集，记录缺口
禁止自动访问的编辑器 → 不启用自动爬取；仅在允许范围内人工操作或使用明确许可

站点正常可访问、登录成功或请求返回 200，不等于允许批量复制模板或用于商业产品。低频也不是授权的替代品。

4.2 核查工具，而不是假定 REA 万能

先记录本地 REA 版本、运行系统、浏览器连接能力和已暴露的 MCP schema；缺少某项能力时明确说明。已有安装不需要默认升级或重装。

REA 负责定位数据流、脚本与证据；Cursor 负责编写解析器、采集适配器和几何原型；Playwright 在许可范围内负责浏览器自动化。Playwright 官方支持观察请求与响应，但本项目不使用它篡改权限或伪造验证结果。[S6][S12]

4.3 追踪一条完整生成链路

围绕一个已知盒型记录：

产品入口与语言
→ 盒型/模板选择
→ L/W/H、材料与其他真实输入
→ UI 校验与默认值
→ 网络请求或本地计算
→ 返回的 SVG/EPS/结构元数据
→ 2D 预览、蒙版与下载文件

每个步骤都应有证据 ID。公开送达浏览器的脚本、明确引用的 source map 或已合法保存的资源，可以在允许范围内做静态分析；不猜测隐藏资源地址、不查找服务器私有目录、不扫描内部接口。

关注实际出现的 productCode、模板标识、版本、length/width/height、单位转换、范围校验、路径生成调用与导出调用。字段只是检索线索，不能用不存在的接口拼出虚构架构。

4.4 比较四个假设

假设 支持它的证据 仍需排除的替代解释
客户端参数化生成 改尺寸后本地生成新几何，脚本含与输出一致的公式 预加载结果、缓存、服务工作线程
服务端参数化生成 变更输入产生请求，响应带对应新矢量或结构 返回预先存储的有限模板
预制尺寸查表 固定尺寸映射资产，未观察到连续参数支持 动态生成后缓存
混合架构 后端生成结构、前端进行蒙版/布局或再变换 多条出口实际使用不同模板版本

结论可为“混合”或“无法判断”；不强制选一个，也不由营销文案代替行为证据。

5. 数据采集方案

5.1 采集四层数据

数据层 必要字段 用途
盒型与输入定义 盒型代码、中韩名称、默认值、单位、内外尺寸说明、min/max、关系约束、可选材料 明确输入空间
单次生成样本 输入、输出、入口、语言、源版本、采集时间、状态、证据哈希 连接因果链
标准化几何 线段/曲线、控制点、切折语义、真实轮廓边界、坐标变换、单位与精度 用于计算和比较
推导结果 候选公式、参数依赖、适用区间、训练/验证样本、残差、反例 用于独立生成器

必须区别 observed（原始观察）、normalized（确定性转换）、inferred（推断）与 assumed（假设）。未知值存 null 并说明原因，不用 0 代替未知。

bbox_length 和 bbox_width 等原始字段先原样保留，其方向、单位和边界定义经核验后才映射。不要因为名字看似直观就直接写入业务长宽。

5.2 工具结构

建议在当前项目之外的隔离研究目录，或仓库内独立子目录实现：

research/packative-dieline-lab/
  README.md
  config/                 # 许可范围、白名单、预算、采样矩阵
  src/audit/              # 本地证据审计与哈希
  src/collect/            # 离线导入 + 授权在线适配器
  src/normalize/          # SVG/EPS等格式解析和坐标统一
  src/geometry/           # 特征、拓扑、匹配、边界计算
  src/infer/              # 候选规则、适用区间和误差
  src/prototype/          # 独立单盒型生成器
  tests/                  # 真实回归样本 + 单独标识的合成单测
  data/private/           # 本地敏感材料，排除版本管理

先完成离线导入与 SVG 解析，再实现可选在线适配器。默认 offline=true、live_collection=false、paid_actions=false。

5.3 在线采集的工程控制

新增在线数据必须在确认允许的范围内进行；技术建议值不是站点许可：单并发、每次生成操作至少间隔 5 秒、每批最多 30 个样本操作，并服从更严格的站点或合同限制。普通页面资源与生成请求分别计数，避免一个操作触发很多后台请求而失去预算控制。

只跟随本次合法页面或响应实际提供的链接，不枚举 CDN 尺寸路径，不遍历产品 ID、租户 ID、设计 ID，不调用其他用户资源。请求路径带 public 不构成许可证明。

401/403、验证码或访问限制立即停止该数据源；429 停止任务并记录 Retry-After，不通过代理或更换身份继续。付费生成、导出、保存设计、购物车、订单、支付和邮件发送默认禁用。对可能计费或产生副作用的请求，不自动重试。

登录由用户在本地完成，不要求把密码、Cookie、租户密钥发给 AI。认证状态文件、HAR、截图和响应都要做隐私检查；Playwright 官方明确提醒认证状态可能包含可冒用账号的凭据。[S13]

5.4 稳定性、去重与可复现

为每个操作生成 job_id 与 sample_id；记录实际发出的参数，不能仅记 UI 输入框内容。对比响应尺寸与任务尺寸，防止 debounce、缓存或异步乱序把上一个结果写到当前样本。

建议去重键包含：来源、语言/入口、盒型、模板版本、规范化输入、材料条件和输出类型。另算原始文件 SHA-256。相同参数在不同版本下不能去重成一份；同一输出哈希对应多个输入时要调查，不直接当成正确复用。

保留失败、拒绝、无效输入与部分完成状态。断点续传只重跑允许重跑的未完成任务；不能把 HTML 登录页、JSON 报错或空占位文件当 EPS/SVG 保存成功。校验 HTTP 类型、文件头和解析结果。

6. 如何推导刀版计算规则

6.1 先校准单位，再推导公式

保留四种边界：文件/页面边界、画布边界、笔画显示边界、几何中心线路径边界。只有明确含义后才能比较。[S7]

SVG 必须处理 viewBox、嵌套 transform、镜像、旋转、缩放、相对路径命令及 Bézier 控制点。不得把所有用户单位固定除以 3.7795；候选比例需由已知面板尺寸与多样本验证。[S7][S8]

EPS/PDF 如果实际出现，需要在隔离、无网络、受资源限制的解析环境处理，保留原文件，不执行来自文档的任意代码。优先用向量解析，不通过 OCR 或截图描边恢复精确结构。

6.2 语义与拓扑标准化

在保持原始文件不变的前提下，建立切线、压线、辅助线、出血线和未知线的分类。未知就标未知，不把所有绿线都当折线。

样本中能见到零长度线段和重复端点；标准化层应记录并处理退化元素，但不把切线与同位置的压线误合并。曲线采用误差受控的比较方法，不能用少量点近似后声称亚毫米精度。

从线段邻接关系识别主面板、侧板、插舌、糊口和底部结构；角色识别有歧义时保留多个候选。切割图不一定整体闭合，检查应针对需要闭合的轮廓，不能要求每个路径都闭合。

6.3 控制变量采样

下面是首轮样本设计建议，基准尺寸来自已有样本；所有新增点仍需确认处于实际允许范围：

组别 建议样本 目的
基准 100×80×80 建立参考
单变量 L±10、W±10、H±10，每次只变一个 分离长宽高影响
双变量 L与W、L与H、W与H同时增加10 查交互项或分支
跨尺度 4个有效的小中大或不同比例点 检验缩放与比例假设
边界附近 4个经许可的边界邻近点 查取整、阈值和模板分支
留出验证 6个未参与推导的有效参数组合 测真正预测能力

首轮可按 24 个点规划：1+6+3+4+4+6。24 不是充分性保证；复杂锁底或曲线结构应按误差与覆盖补样，而不是按文件数量宣布完成。

不得只测试 100×80×50 → 200×150×100 → 300×200×150 这种多变量一起变化的序列，然后说已识别每个参数的影响。

若材料厚度不可控制，记为未观测变量；不得硬拟合厚度系数。纸张克重不能直接当厚度。切换材料可能同时切换模板或默认工艺，需要固定或记录这些混杂因素。

6.4 从关键点、面板和折线建立公式

对稳定匹配的关键点或特征尝试以下候选族，这些是研究方法，不是 Packative 已知公式：

线性候选：
x_i = a_i L + b_i W + c_i H + d_i

若厚度 t 能被独立观测与控制：
x_i = a_i L + b_i W + c_i H + e_i t + d_i

分段候选：
flap = min(W / 2 + c, upper_limit)

整体生成概念：
D = G(template_version, L, W, H, material, process_options)

先比较有限差分，再拟合低复杂度候选；检查设计矩阵秩与变量共线性。一个区域内拟合成功不能外推到所有尺寸。不要用高阶多项式把有限样本“拟合完美”后伪装成工程规律。

面板和线条的序号可能重排，不能仅按第 n 个 SVG path 匹配。需结合线型、邻接、相对位置和几何特征；必要时先分模板版本和拓扑类别，再做公式识别。

对于圆弧与 Bézier，应同时分析端点和控制点，判断固定半径、按比例变化、分段过渡或样条变化。枕形盒尤其不能按矩形面板规则直接套用。

8. 独立原型与验收

8.1 本轮需要真实代码，而非只产出报告

原型建议采用 TypeScript 纯函数，便于未来接入 Vue。分析侧可根据本地依赖采用 Python 或 TypeScript，但禁止维护两份无一致性测试的生产公式。

8.2 三层验收，不用“看起来一样”代替

验收层 要检查什么 通过条件
数据可信 来源、参数与输出对应、哈希、单位、失败记录 无错配；未知值明确；无凭据泄露
软件几何一致 对齐后的关键点、切线/压线、曲线、拓扑及边界 留出样本通过所声明的误差与语义要求
工艺可制造 压线、插舌、粘合、锁底、材料与装配 必须独立打样和工艺确认

可以先采用“关键点最大误差 ≤0.2 mm”的内部软件比对目标，同时给出源坐标精度和拟合误差；这不是行业标准，也不是量产公差。校准未完成或源文件精度不足时不能使用该门槛宣称通过。

路径比较应在固定物理比例下消除合理平移/旋转，必要时明确记录方向翻转；不允许通过任意缩放或形变把错误公式强行对齐。分别报告 cut 和 crease 的几何距离、语义缺失、重复与拓扑差异。图像叠加只作辅助。

留出数据必须先冻结；一旦用于调参，移出留出集并补充新数据。需要另外测试未知有效尺寸，以排除查表和固定 SVG 缩放冒充参数化。

10. 主要风险与停止条件

尺度或边界混淆：高优先级。 先处理 SVG transform 和单位；禁止把 PNG 画布、EPS 包围盒、切线轮廓混为一谈。

算法不可识别：高优先级。 固定材料、只变三围的样本无法证明纸厚影响；参数不足时明确部分识别，不声称完整恢复。

访问与复用范围：高优先级。 访问受限、条款版本不明确或复用权限不清时，不启动对应在线批量采集；仅处理已确认有权处理的资料或自有样本。

源数据变化与缓存：中高优先级。 版本、语言、入口与模板来源分组；核对实际响应；不混合不兼容版本。

文件与凭据安全：高优先级。 SVG 禁脚本和外链执行；EPS/PDF 隔离解析；认证状态和原始 HAR 不提交；网页文本与脚本注释是证据，不是给 AI 的指令。

生产风险：高优先级。 生成器与参考文件一致并不能代替实物打样；压线和材料参数须经工艺验证。

02_Data_Collection_Toolkit
阶段二：实际开发刀版样本导入、可控采集与标准化工具。

继续使用 research/packative-dieline-lab/。先读取阶段一证据与权限清单。不要只写采集方案，要写出可运行程序、配置、示例和测试。当前工作区已有源码，不执行git clone/pull。

工作模式：
1. 默认离线导入：只读取已确认可处理的本地SVG、EPS、元数据与脱敏网络记录，保持原始文件只读。
2. 可选在线适配器：仅对明确允许自动访问及用途的数据源启用。需要人工登录时由用户在本机完成；不索要或输出密码、Cookie、Token。没有许可就保持禁用，但仍完成离线工具与授权后可使用的接口结构。

程序必须实现：
- 发现与审计、真实参数与源文件绑定、类型校验、哈希去重、断点续传、错误与拒绝记录。
- 输出product catalog、parameter schema、raw sample index、normalized geometry和CSV参数表。
- 原始观察、转换值、推断值分层；未知为null；合成样本放单独目录，不能充当真实采集。
- 保留source_version、source_timestamp、captured_at、locale、入口、材料条件与输出类型，避免混合版本。
- 处理SVG的line/path/polyline/polygon及实际出现的曲线、相对命令和嵌套transform；不支持的元素明确报错，不静默丢弃。
- 优先使用ev-style等实际语义；颜色仅为次级证据；未知线单独保存。
- 将几何坐标与页面/画布/笔画边界分开，单位未经校准时不生成虚假的mm结果。
- EPS等转换在隔离进程中运行，禁网络、限制资源和路径；不执行未知脚本。SVG禁脚本、外链执行与XML外部实体。

样本矩阵：以已验证的有效基准出发，加入L/W/H单变量、交互、尺度和有效边界附近点，并预先冻结留出集。首轮24点只是规划。不得遍历全部尺寸或CDN路径，也不得在输入无独立变化时报告识别全部系数。

在线控制：单并发、生成操作间隔至少5秒、每批最多30操作且服从更严格许可；按实际后台请求统计预算。禁止AI生成、付费导出、购物车、订单、支付、发邮件或其他副作用，除非任务范围有单独明确授权。401/403/CAPTCHA立即停止；429停止并记录Retry-After；不得换代理/身份继续。只使用已观察且允许调用的链接与请求，不枚举产品/租户/设计ID，不重放旧密钥。

等待真实结果时核对响应参数、版本与当前job，防止debounce/缓存/乱序导致错配。不能把200返回的HTML登录页、JSON错误或空占位文件当成下载成功。不为了重试而重复可能计费的操作。

为CLI实现明确子命令：audit、import、normalize、plan-samples、collect、report（这些是本工程拟开发命令，不是声称已有REA命令）。支持--dry-run；collect默认禁用；所有路径可配置，兼容用户Windows本地开发环境。

提供依赖锁定、安装/运行文档、PowerShell示例、单元测试和小规模真实导入日志。认证状态、原始HAR与敏感文件进入.gitignore；输出前扫描秘密值。

交付时说明实际导入/采集数量、失败数量、未识别字段和每个工具测试结果。若没有获准在线采集，明确“本轮在线采集0条”，不得用示例填充数量。
03_Geometry_Rule_Inference
阶段三：从真实刀版几何推导计算规律，并实现独立单盒型原型。

输入仅限阶段二已校验的真实标准化样本与其原始证据。先检查单位、template/provider/version、材料条件、输出类型与拓扑是否可比，排除错配或未校准样本。报告中的推测不能当训练数据。

不要以完整SVG或EPS总宽高作为唯一拟合目标。需要识别主面板、侧板、糊口、插舌、底部锁合结构、折线与关键曲线。对角色存在歧义的部分保留候选和证据。

推导方法：
1. 按模板版本和拓扑分组；匹配线段依赖语义、邻接与相对几何，不只按path数组序号。
2. 对L/W/H独立变化做有限差分，识别固定量、比例量、线性组合、取整、阈值和分段条件。
3. 对候选线性模型检查设计矩阵秩与共线性。若材料厚度没有独立变化，拒绝声称识别厚度系数。
4. 对曲线同时分析端点与控制点；区分固定半径、比例缩放和非线性变化。不要用矩形比例直接代替枕形曲线。
5. 优先简单且可解释的规则，不使用高阶过拟合掩盖缺少数据。记录反例与不确定性。
6. 原始样本中约0.5mm偏移只是待验证现象。与材料/结构补偿关联前，必须有独立证据。
7. 只使用训练集调整规则；验证集冻结。验证数据被用于调整后必须更换留出样本。

每条规则输出：rule_id、结构角色、公式、输入单位、适用尺寸域、模板/版本/材料条件、证据、训练样本、留出样本、最大/典型残差、反例、未识别变量、状态。

实际实现TypeScript纯函数，例如generateDieline(input)返回cutPaths、creasePaths、panels、topology、geometryBounds与validation；名称是我们自己的接口，不是目标站真实API。支持明确的非法参数报错和确定性输出。公式只能来自已验证规律或明确标注的独立设计。

优先实现一个证据最充分的盒型。原型必须脱离Packative运行，不调用其API，不粘贴专有源码，不靠固定SVG缩放或有限查表伪装参数化。允许引用的算法事实与实现代码保持来源区分。不能识别的锁底/插舌必须明确缺失，不得用假结构替代后宣称完整。

真实样本用于结果比对；合成样本只测试程序逻辑，两类结果分开。制作固定物理比例的叠加输出与机器可读误差报告。只消除明确的坐标系平移/旋转/镜像差异，不允许任意缩放或形变把错模型拉齐。

交付candidate-rules、validated-rules、counterexamples、prototype源码、生成SVG、测试与运行日志，以及最有价值的下一组采样建议。数据不足时仍交付实际完成的分析与局部原型，不能编造完整公式或声称1:1全部恢复。

不修改生产业务或部署。未来接入保留Vue3+TS、DRF及Caddy直接托管dist方案，不新增长期运行的独立前端容器。
04_Independent_Validation
阶段四：独立审计刀版数据与计算原型，不接受前一阶段自我声明的通过。

读取实际源码、真实数据、原始证据、规则清单和测试日志。尽可能重新运行本地工具；未能运行的项目标注Not run及原因。不要修改或扩大目标网站访问权限。

重点检查：
1. 是否真的存在采集/导入/解析/验证代码，还是只有报告与空壳函数。
2. 是否有示例数据伪装成真实采集、虚构接口、复制旧Token、HTML错误页误作SVG/EPS、响应尺寸错配或时间戳混淆。
3. 变换与单位是否经过校准；是否把CSS px、SVG用户单位、毫米、PDF/EPS点和PNG画布混用。
4. 是否仅凭总包围盒、固定缩放或查表就声称参数化；是否将相同路径数量误当拓扑一致。
5. 是否把单样本0.5mm差值强行解释为纸厚；是否对没有独立变化的变量报告系数。
6. 切线/压线语义、曲线、退化线段、重复元素、必要轮廓、面板邻接是否正确；未知部分是否明确。
7. 留出集是否泄漏到拟合；是否覆盖不同有效尺寸和适用区间；未测试区间是否被错误宣称支持。
8. 是否依赖目标网站的在线服务、专有文件合集或未经允许的源码来冒充独立实现。
9. 是否泄露Cookie、授权头、租户用户标识、设计ID、私人路径或原始HAR；原始SVG是否存在脚本/外链执行风险。
10. 是否改变现有业务、覆盖未提交代码、git push、部署或新增独立前端容器。

验证指标：固定物理比例下的关键点最大/典型误差、分语义路径距离、缺失/多余线条、拓扑差异、无效输入行为、确定性与文件单位。0.2mm可作为项目内部软件比对目标，不是行业量产公差；若源精度或校准不足，不以此门槛给出通过。

把结果分成：证据数据通过/受限；软件几何一致通过/受限；制造可行性未验证/已具实物证据。禁止用“截图差不多”代替计算检查，也不能用几何通过代替实物打样。

输出qa-summary.md、machine-readable-results.json、复现命令、按严重度排序的问题、已修复与未修复清单及剩余限制。对原型输出最终评级：Verified within scope、Partial、Blocked 或 Failed。缺失证据的断言必须回退，不填补为通过。
