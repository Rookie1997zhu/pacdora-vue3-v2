# 一、背景与动机

- 公司正式网站 **MASSCONNECTED.COM** 上，已具备「包装结构示意 / 开合预览」相关能力。  
- 上线后实际使用反馈：**效果未达预期**，业务侧难以稳定依赖其做选型、沟通与对外展示。  
- 行业内 **Pacdora** 在同类场景上体验更完整，适合作为对照与学习对象。  
- 因此启动专项：对 Pacdora **做逆向分析并采集必要样本数据**，先做出**独立功能样机（Demo）**，把「该做成什么样」跑通、看清。  
- **样机验证通过后**，再将成熟能力**移植回 MASSCONNECTED.COM**，服务正式业务。

---

# 二、既有能力为何不够用

结合正式站使用情况，主要痛点可归纳为：

| 方面 | 现象（业务语言） |
|------|------------------|
| 结构可信度 | 示意与真实运输箱差异大，客户与内部沟通成本高 |
| 开合观感 | 开合过程生硬或不同步，难以表达「怎么折、怎么合」 |
| 目录与范围 | 结构混杂、重点不清，运输箱场景不够聚焦 |
| 落地交付 | 缺少清晰的尺寸标注与可交付的设计稿形态，后续衔接弱 |

**结论：** 不是「有没有功能」的问题，而是「是否足够贴近真实业务、是否能拿来用」的问题。

---

# 三、总体思路与工作路径

```text
正式站体验不理想
        ↓
以 Pacdora 为对照：逆向分析 + 样本采集
        ↓
独立样机：聚焦运输箱，先把主路径做实
        ↓
内部核对、反复修正观感与逻辑
        ↓
确认后，再移植到 MASSCONNECTED.COM
```

**原则（汇报口径）：**

- **先样机、后迁入**：不在正式站上反复试错，降低对现网的干扰。  
- **先对齐真实、再谈扩展**：运输箱目录与官方样本优先。  
- **对内可演示、对内可核对**：看得见开合、看得见展开、看得见尺寸与导出。  
- **明确边界**：样机用于验证方向与交互；正式生产刀版与量产开模仍走既有工艺与审校流程。

# 四、本阶段主要成果（概览）

本阶段独立样机已形成一条可演示的主链路：

1. **目录收敛**：运输箱场景下，展示范围清晰、可检索。  
2. **真实结构回放**：对采集到的官方样本，能按真实结构展开与合盖。  
3. **分步开合**：合盖过程有步骤感，多件组合也能按整体理解开合。  
4. **二维展开可读**：刀版图上可看裁切、折线、出血与尺寸。  
5. **对外交付形态**：支持导出多种常用设计稿格式，便于内部流转与沟通。  
6. **观感与相机**：打开后三维预览默认居中；出血外扩更易辨认。

以下分页展开。

---

# 四（1）目录与范围：先把「运输箱」说清楚

- 将演示重点收敛到**运输箱**相关结构，避免目录过宽导致选型困难。  
- 列表侧可按名称、编号等方式查找，进入工位后尺寸对官方样本**锁定试播**（先看准结构，再谈改尺）。  
- 列表封面尽量呈现**合盖后的立体观感**，减少「点进去才发现不是想要的」的成本。

**业务价值：** 对内演示、对客讲解时，范围清楚、重点突出。

---

# 四（2）真实结构：从「示意」走向「可对照」

- 对 Pacdora 侧采集的运输箱样本，在样机中按**官方结构**进行展开与合盖回放。  
- 特别处理了**需要两张（或多张）刀版拼在一起才能开合**的箱型：拼合与开合按一整套理解，而不是各动各的。  
- 合盖终态做了外形合理性核对，避免「看起来合上了，实际散开变形」。

**业务价值：** 沟通时能对齐「真实箱子大概长什么样、怎么开合」，而不是停留在抽象示意图。

---

# 四（3）开合体验：要有步骤感

- 合盖进度可从完全展开拖到完全闭合，过程**分步进行**，而不是所有面同时翻折。  
- 界面可提示当前大致处于第几步，便于讲解「先拼、再折、再合盖」。  
- 多件箱型同样遵循分步逻辑，避免演示时观感混乱。

**业务价值：** 销售、结构、客户三方可共同看懂开合顺序。

---

# 四（4）二维刀版：看得懂、标得清

在二维展开图上，样机已支持：

- **裁切线 / 折线 / 出血示意**分层显示，可单独开关；  
- **整体长宽高**与**各主要面板宽高**标注；  
- 出血相对裁切**默认再外扩约一厘米**，绿线与蓝线更易区分（示意用途，非量产工艺最终稿）。

**业务价值：** 内部评审与对外说明时，「展开长什么样、尺寸落在哪里」一目了然。

---

# 四（5）导出与交付形态

样机支持将当前刀版导出为多种常用形式，例如：

- 矢量图稿、工程交换稿、校样用文档；  
- 以及设计软件可直接打开的兼容稿（便于设计同事二次编辑）。

说明：导出内容定位为**技术校样 / 沟通稿**，样机侧明确**不可直接用于开模量产**，正式开模仍须走公司审校与工艺确认。

**业务价值：** 缩短「看演示 → 拿文件去改、去议」的路径。

---

# 四（6）使用体验修补（近期）

针对试用中的直观问题，已完成一轮修正：

| 问题 | 处理结果 |
|------|----------|
| 打开刀版后立体预览常常不在画面中央 | 打开与重建后自动对准，无需先手动拖找 |
| 出血线与裁切线几乎贴在一起、不易分辨 | 默认加宽外扩，并修正外扩算法，避免轮廓「画坏」 |
| 多件箱型开合不像一整套 | 按官方动作回放拼合与折叠，合盖外形纳入核对 |

# 五、质量核对与验收情况

样机侧建立了固定核对习惯（对内汇报口径）：

- **结构与合盖**：重点箱型合盖后外形与样本尺寸量级一致，异常会拦截。  
- **目录完整性**：运输箱展示清单与「有几何可播」状态对齐。  
- **导出可用性**：主要导出通路可生成文件并带必要免责说明。  
- **目视抽查**：选取多款典型运输箱（含多件、带提手等）做打开—拖进度—看刀版抽查。

另：样机已具备**线上演示入口**，便于异地同步查看（正式迁入前仍以样机环境为准）。

---

# 六、下一步：移植到 MASSCONNECTED.COM

样机目标是「把事情做对」；正式站目标是「把事情用起来」。建议迁入节奏：

1. **范围对齐**  
   明确首期迁入：运输箱目录、真实结构试播、分步开合、二维标注与导出中的哪些能力。

2. **体验对标**  
   以本样机为体验基准，对照正式站现有能力做差异清单（观感、步骤、多件、导出）。

3. **账号与业务流衔接**  
   与 MASSCONNECTED.COM 既有登录、订单、材质与报价等流程对接，避免「只会演示、接不上单」。

4. **数据与版权边界**  
   明确官方样本仅用于对照与试播策略；正式站对外内容的授权、更新与免责口径由业务与法务确认。

5. **灰度与验收**  
   先内测、再小流量，按「能讲清、能选对、能导出沟通稿」做验收，再全量替换旧体验。
