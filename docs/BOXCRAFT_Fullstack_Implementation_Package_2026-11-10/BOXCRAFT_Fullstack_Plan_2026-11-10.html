01｜结论与项目边界

目标：以现有 BOXCRAFT LAB 为基础，独立实现 Packative Studio 研究所记录的页面、操作与业务闭环，同时保留已有刀版、3D 折叠、运输箱目录和外箱装箱功能。不是推倒重写，也不是只制作静态页面。

建议技术路线：Vue 3（旧 JS 保留，新模块 TypeScript）＋ Konva 设计画布 ＋ Three.js 结构预览 ＋ Django REST Framework ＋ PostgreSQL ＋ Redis/Celery ＋ Caddy ＋ Docker Compose。后端以 Django 为本方案的实施选择，并非当前仓库已有实现；不将项目强行迁入 Sites，也不为了模仿目标站而更换成 Next.js/Supabase/EngView。

先纠正研究报告的项目基线。研究第 08、09 篇中的 global-toolbox-vue3、integrations/dieline、Django apps、engine-ts、deploy/compose.yaml，描述的是另一个 PackFlow 工程。它们不在本次指定仓库的已核对根目录和代码树中。因此，本方案不能把“复用已有后端”当成事实。[R08][C01][C02]

需要在开发前登记的差异与风险

F-01：研究基线错位。 第 08 篇“已有 Django/Celery/Caddy”不能用于当前仓库；后端、认证、数据库和部署必须新建。若开发者本地确实还有未推送后端，只能先识别真实文件和契约，再增量整合，不能凭研究文字断言存在。[R08]

F-02：说明文字与当前几何加载代码不完全一致。 README/目录注释强调“只导入尺寸”，但 App 的 geomMode 会走 loadPacdoraGeomKnife()，读取公开目录下的几何快照。实施时以代码路径为事实，补齐来源与授权登记，不静默删除既有条目，也不把研究快照直接升级为生产资产。[C03][C05][C06]

F-03：PDF 当前不是明确的 1:1 毫米输出链。 toPdf() 用 wMm/hMm 计算 pageW/pageH，再适配页面缩放；这一函数没有显式 72/25.4 转换。因此旧 PDF 应继续标成校样稿，新增毫米标尺回归后才能宣称 1:1。SVG 只有 viewBox，没有明确 width/height="...mm"，也要补物理尺寸契约。[C08]

F-04：生产资格不能从拓扑通过推导。 manufacturingReady=false 是现有明确边界；productionReady=validation.ok 只表示代码契约通过。cutApprox、bleedApprox、AABB 闭合示意、补偿系数和 BLEED_EXTRA_MM=10 都要保留、记录或单独评审；不能删除 DEMO 文案就宣称能开模。[C04][C07][C08][C10]

F-05：样机、固定快照、自研参数模板是三种能力。 模板具有面板不等于支持制造；固定快照不等于支持尺寸编辑；3D 看起来闭合不等于曲面应变、厚度和糊口已验证。[C03][C05][C07]

F-06：无现成的设计业务持久化。 当前状态主要在前端内存；语言 localStorage 不能当成云端保存。新建用户、设计、版本、资产、AI 任务、导出、购物车和订单域，禁止仅用 localStorage 冒充后端。[C02][C03][R08]

视觉验收方法

按同一 viewport、缩放、语言、页面状态截取参考与实现图，生成叠加图和差异图。先验收区域布局、位置、间距、字体层级、控件大小，再比较细节。AI 生成图片、用户名、价格、时间等动态内容使用固定测试样本或遮罩，不让随机差异淹没布局问题。建议从 1440×900、1920×1080、768px 和 390px 四档验收；这些是本项目测试档位，不是已测目标站参数。

约定门槛：关键布局不存在错位/覆盖/不可点击；同语言主要控件位置建议控制在 2–4 CSS px 的审阅容差内；视觉差异阈值由首批基线实测后冻结。不能只凭一个 SSIM 分数宣称“100% 一样”。品牌标识、授权字体和自有素材的差异单独列为批准差异。

移动端维持目录、账户、设计预览、订单可用；复杂 Studio 提供明确的简化编辑或桌面使用提示，不能展示不可操作的桌面画布。默认中韩完整；英语为后续扩展，不以缺失韩文文案的英文占位交付。

保存版本的事务

请求带 expected_row_version 和 Idempotency-Key。后端先验证设计归属、文档 schema、资产权限、模板能力，再取得可信几何结果；进入短事务时重新锁定/检查版本，插入不可变 revision，更新 current_revision 与 row_version，同时写入必要 outbox。不要在数据库锁持有期间调用慢 AI 或执行长几何计算。

同一幂等键＋同一规范化请求返回原结果；同一键但不同 payload 返回 409。并发保存失败时返回 DESIGN_VERSION_CONFLICT 和当前版本，不静默覆盖。前端展示“重新载入 / 保存为副本 / 人工合并”，不能把 HTTP 200 当成所有冲突都已处理。

设计与任务状态机

Design: active -> archived -> active
AI/Export Job: queued -> running -> succeeded
                             |-> failed
                             |-> cancelling -> cancelled
Quote: draft -> valid -> expired / superseded
Order: submitted -> awaiting_quote -> quoted -> confirmed
                                      -> cancelled
       confirmed -> in_production -> shipped -> completed

支付状态与订单/生产状态分开；无支付渠道时允许真实询价/人工确认订单，不伪造 paid。任务取消是协作式：若供应商请求已经发出，结果可能到达；服务端必须记录状态、隔离过期结果并按实际计费策略处理冻结配额，不承诺立刻停止供应商计费。

{
  "code": "OK",
  "message": "成功",
  "data": { "id": "uuid", "row_version": 3 },

建议状态码：400 输入错误、401 未登录、403 已知对象无权、404 不存在或隐藏资源、409 版本/状态冲突、413 过大、422 合法结构但不满足制造条件、429 限流、503 所需供应商/服务不可用。具体采用 403 还是隐藏为 404 要统一；DRF 认证/异常处理应通过测试确保与此契约一致。

公开工具与登录的边界：原来可匿名运行的本地刀版/装箱继续匿名可用；云保存、私有资产、AI、购物车和订单需要登录。不能新增登录墙把旧功能整体锁住。

几何契约扩展

保留 boxcraft.knife.v3 兼容读取；Studio 使用版本化适配输出，增加面板稳定 ID、外/内表面、可印区、胶区、锁舌、出血、安全区、曲线路径和制造警告。单件平板可为铰链树，多件组合允许森林；曲面包装具有独立曲面参数化与 UV，不能强行套“faces-1 个 hinges、单一 root”的旧检查。[C04][C07]

Pillow/半月盒是独立研发项。 研究提供了 SVG/EPS/CAD 观察，未提供完整公式。需要自研/合法授权结构规范、曲线保留、自适应三角化、曲面 UV 和折叠近似级别；不能把 cylinderBox 改名就算完成，也不能通过线性缩放一个 PNG 得到新尺寸刀版。[R05][R06]

模板范围与验证

首个垂直闭环优先选择已有稳定 mailer 模板；再完成 crash-lock 对应模板、sleeve、tray、pillow。目录名称到内部模板必须维护显式映射，不以名字近似作为已还原的证据。研究中 crashlock L/H 25–400、W 25–350 与比例约束可作为比较用例，但它们是该目标产品的观测值，不是本项目所有模板的通用物理规则。[R05][T04]

每个模板记录最小/默认/最大、至少三组非等比尺寸、非法/比例边界、材料厚度边界和多件情况。服务端严格拒绝 NaN、Infinity、字符串注入、超大层/多边形；旧 UI 的夹取行为保留在原工具，新正式 API 应返回校验提示，不能默默改变客户订购尺寸。

浏览器与服务器的同源校验

同一模板版本和参数输入，在浏览器构建产物与 Node 容器中输出相同规范化结构；比较稳定面 ID、拓扑、层类型、bounds、参数与舍入后的坐标。建议数值比较容差先设为 0.001 mm，再根据现有舍入和不同算法明确适用范围；该容差是软件一致性指标，不是加工公差承诺。

几何哈希使用规范化 JSON：稳定 key 顺序、约定浮点精度、去除相机/时间戳、明确数组顺序；写入 engine/template 版本。哈希来自可信服务器计算，不接受客户端自报值。生产复算失败返回业务错误并保留诊断信息，不能降级成默认盒型或近似 AABB 继续生产。

12｜2D 设计编辑、UV 与保存复开

编辑器选型决定

研究第 04 篇建议先做 SVG 轻量交互，这是适合最小增量的建议；本次目标已经包括复杂图层、文本、形状、裁剪、局部编辑与历史，因此新增 Studio 采用 Vue + Konva；原 SVG 刀版与 LegacyLab 不删除。选择理由是功能范围，不是必须复制对方内部栈。Konva 与 Three.js 只渲染自己的投影，不互相直接修改状态。[R04][O05]

统一坐标与两类画布对象

刀版世界坐标统一 mm、Y 向下；面板局部坐标以模板明确锚点为原点。普通图片/文本/Logo 多使用 panel_mm；主区域生成的整张展开图使用 net_mm。Canvas 像素、缩放、设备像素比只能属于渲染层，不能作为持久化尺寸。

netMm = panelToNetMatrix × panelMm
canvasPx = viewportMatrix × mmToPxMatrix × netMm
u = (netX - atlasMinX) / atlasWidthMm
v = 1 - (netY - atlasMinY) / atlasHeightMm

这组 UV 是拟定约定，实际 mesh UV/CanvasTexture.flipY 只能在统一适配器中处理一次；禁止两处重复翻转。测试使用不同颜色四角、箭头、左右文字和跨面接缝，不用对称图形掩盖镜像。纸板边缘材质与外表面印刷材质分开，孔洞不能被整张贴图填平。色彩图使用合适的 sRGB 标记，法线/粗糙度不作为颜色图处理。[O06]

更改尺寸时不丢图案

按图层 resizePolicy 执行：Logo/文字默认保持真实 mm 尺寸＋锚点；底纹可随面板缩放；整版生成图按其生成时几何哈希关联，几何变动后明确显示需重新适配/重新生成，不能默默拉伸成“正确新设计”。面板被移除或模板切换时，受影响图层进入待处理列表，允许重新绑定，不能直接丢弃。

原外箱设置也保存到 DesignDocument 或独立 PackagingPlan 引用；恢复方案时 grow/fixed、数量、间隙、手动排列、外箱目录项均还原。不得只保存主盒尺寸而遗失用户装箱工作。

撤销、重做与版本

画布操作采用 command/transaction：一次拖动只生成一个历史步骤，而非每帧一个。撤销/重做包含新增、删除、排序、文本修改、裁剪、面板重绑定与参数改变；AI 任务本身不能靠本地撤销撤销供应商扣费，应用 AI 结果可以撤销为一个画布命令。

自动保存建议在停止编辑约 1–2 秒后触发，并设置最短提交间隔；未结束的拖拽不提交。未保存状态与服务器确认状态分开显示。断网时写入 IndexedDB 恢复草稿并清楚标记“仅本机”；恢复网络后先检查 row_version，不能覆盖其他窗口的新内容。

完整保存闭环

文件上传并验证→文档引用 asset ID→保存 revision→服务器返回确认版本→异步生成缩略图→离开页面/硬刷新/重新登录→重新读取文档、几何版本与资产→重建 2D 和 3D。截图只能作为缩略图，不能代替可编辑 JSON。缩略图仍在不等于文字/图层可编辑状态已恢复。[T01][E02]

3D 性能与生命周期

图案变化仅重绘受影响 atlas/纹理，折叠只更新 transform，不重建全部几何。结构参数变化才重算/重建 mesh。分辨率按预览与导出分级，纹理上限读设备能力；后台页停止渲染循环，卸载释放 geometry/material/texture、ResizeObserver、事件和 animation frame。对大目录延迟生成缩略图，避免一次创建几十个 WebGL renderer。

供应商边界

默认实现一个真实图像生成/编辑适配器，建议以 OpenAI Image API 的官方生成与编辑接口为首个适配目标；模型 ID、允许尺寸、能力与费用配置在服务端管理，实施时固定并测试实际可用版本。官方提供生成和编辑能力，但这不等于原生提供本项目包装主区域设计、生产 CMYK 或所有图像后处理；这些由本项目组合实现。[O07]

generate/edit/remove_background/vectorize/upscale 使用能力注册表，不假定一个 API 全包。矢量化与背景移除可采用独立处理器/供应商；使用开源处理器前核对代码、权重和运行许可。没有配置的功能返回 CAPABILITY_UNAVAILABLE，界面明确禁用，不回传演示图标成成功。不支持的 seed、尺寸或多图参数不能硬塞给供应商。

主区域生成的实现链

  1. 固定输入 revision；服务器读取可信几何并产生 netBoundingBoxMm、mainMask、printableMask、totalMask。每个 mask 存 hash、像素大小、正反相约定和 mm→px 矩阵，不沿用对方文件名来猜黑白语义。
  2. 将主面/整个展开图映射到供应商支持的画布；必要的 padding、裁切和缩放写入变换矩阵。不要硬编码所有盒型都为研究样例的 2048×1216。
  3. prompt 增强只构建风格与内容，不让模型生成刀线、条码或法律必需文字。品牌名、Logo、条码和印刷小字默认作为确定性的矢量/文字图层叠加，避免依赖模型文字精确度。
  4. 生成后执行可印区裁切、保护区处理、拼接/延展策略、尺寸与透明度检查；输出保存 inputGeometryHash 和 atlas 对齐信息。
  5. 展示结果预览，由用户“应用到设计”。任务完成时若当前版本已经变化，显示“此结果基于旧版结构”，要求显式重新绑定/适配，不能自动覆盖。

供应商的 mask 编辑可能不是硬像素保护。要求严格保持的区外内容，通过本地合成把原图区外像素合回；不要仅靠 prompt 承诺“绝不改变未选择区域”。AI 只负责图案，不决定几何、价格、授权或制造资格。

队列、幂等与费用

POST ai-jobs 在同一个数据库事务中写 Job、UsageReservation 与 OutboxEvent，再返回 202。调度器/分发器把 outbox 投递 Celery；worker 取得租约/状态锁后执行。同一个 job 重复投递不重复扣费或重复覆盖结果；业务实现按“至少一次投递”设计，不声称队列天然 exactly-once。

超时分为排队超时、供应商连接/读取超时和业务总时限。请求已发出但响应未知时记录 provider_request_id 并进入人工/自动对账，不能无限重试造成多次计费。仅对明确可安全重试的错误使用指数退避和次数上限。进度展示 queued/running/processing/completed 及真实阶段，不使用定时器伪造 99%。

任务页在刷新后从 PostgreSQL 恢复状态；Redis 丢失时由 outbox 与任务租约扫描补偿。客户取消、配额不足、供应商拒绝、图片审核不通过、无结果、文件写入失败都要有独立错误码与可恢复操作。真实 AI 冒烟测试需要测试账户与预算；缺 key 标记 Blocked，不把 mock 通过当作 AI 已上线。

安全

API key 只在 backend/worker；浏览器直接调用目标站或供应商是禁止路线。上传只引用已审查资产，服务端不对任意 URL 发请求；需要外部导入时采用明确域名允许列表、禁止内网/metadata 地址、限制重定向/大小/超时。用户 prompt 是业务数据，不能指挥 worker 执行 shell、读密钥或访问本地文件。

14｜产品、报价、购物车、订单与管理后台

报价不抄未知公式

研究仅确认对方存在价格 API，未保留完整请求体或价格算法。因此建立自己的规则引擎，不能把猜测公式写成“与 Packative 一致”。[R03]

规则最少覆盖材料、厚度、结构/展开面积、印刷/工艺、数量阶梯、开机/模具等一次性费用、损耗、最低起订量、加成、币种、税费/运费是否含入与有效期。管理员维护的成本与规则是正式数据；初始 seed 仅创建演示规则且明确禁止用于正式报价。没有正式规则时展示“需人工报价”，允许提交 RFQ，而不是返回 0 元或固定金额。

每个 Quote 保存版本、所有输入和明细快照。跨币种时保存汇率来源/时点/舍入规则与后台审批；“使用最新汇率”不能回头改变已确认报价。具体规则由业务配置，架构支持人民币成本与韩元报价，但不在本方案中编造公司成本。

加购与重新编辑

“加入购物车”必须先保存当前 revision，检查模板可售性、参数、数量与报价，再由服务端创建 CartItem。购物车显示固定 revision 的缩略图和配置；点击“修改设计”创建/打开设计工作副本。再次保存后，明确执行“更新购物车使用的版本”，不能让所有旧订单自动指向设计 latest。

下单时服务器再检查 Quote 有效期、配置和数量一致性、地址与客户信息，以一个事务创建 Order/OrderItems 快照；重复提交使用幂等键返回同一订单号。报价变动返回 409 并展示新旧价供用户确认，不静默多收。

首期没有支付商户资料的处理

交付真实的订单/询价闭环和后台确认，不要求杜撰支付渠道。支付适配器与回调路由可开发并测试，但正式按钮在商户配置、验签与退款流程通过前禁用。测试桩只在 test 环境，不能在生产把前端跳转当成付款完成。正式支付和第三方社交登录属于需要外部凭据才能完成联调的集成项，而不是“用假接口临时完成”。

社交登录：有完整后端，但不复制双轨账户缺陷

研究记录了 Google、Kakao、Naver 的登录入口。要达到这部分功能对等，应实现 OAuthProviderAdapter、提供方能力查询、GET auth/oauth/{provider}/start/、GET auth/oauth/{provider}/callback/、账号绑定/解绑与失败返回页面；分别验证各提供方当前官方规范。回调经自己的 HTTPS 域名进入后端，服务端交换凭据并建立统一 User/Organization 会话，不把目标站的 Supabase/Medusa 双账户体系照搬。[R01][R03]

缺少 App ID/Secret、已登记回调域名、商户或邮箱权限时，保留真实适配代码和测试，相关入口显示未启用；邮箱密码登录与核心设计业务继续可用。state、适用时的 PKCE、一次性回调、redirect URI 允许列表、邮箱验证与账号关联是独立测试项。一个提供方成功不能证明另外两个已联通；未经验证的同名邮箱不能自动合并。正式验收把三种渠道逐一记录 Passed/Blocked，不用通用“社交登录完成”掩盖缺项。

后台必须可操作

Django Admin 首期即可提供：产品/分类/模板版本与来源；材料/价格规则版本；客户/组织/成员；设计/版本只读检查与归档；AI 供应商能力、配额与流水；任务失败/重试；导出审核与预检；询价/订单状态；邮件失败与审计。管理员也必须受权限控制，调价/制造审批有操作者与原因，不把 Admin 当作“谁登录都能改所有表”的万能入口。

物理尺寸与文件格式

PDF 的换算使用 pt = mm × 72 / 25.4；矢量尺度不得为了塞进固定纸张而缩放。按刀版真实 bounds、出血和图框计算 page size，正文与标尺在独立区域处理。SVG 明确 width/height 的 mm 与对应 viewBox。DXF 除层名/单位声明外，必须用独立 CAD 读取验证真实长度与版本兼容，不能只 grep 到 TRIM 就算单位通过。

制作 100 mm 标尺与已知矩形验收：数字读取长度先要求正确，打印测试必须关闭“适合页面”；纸张打印机误差另记，不混入算法容差。EPS 从自己的矢量文档通过受控转换器导出，并检查 BoundingBox、路径和颜色语义；转换器进程限时/限内存，禁止把用户 EPS 当任意可执行输入运行。

.ai 的现有 PDF 兼容导出继续标明兼容格式，不承诺 Illustrator 原生对象/专有图层。确有原生 AI 需求时单独定义可接受交付格式与外部工具链，不仅更换扩展名。[C08]

图层、字体、色彩与 PPI

将 artwork、cut、crease、bleed、safe、white-ink 等角色分开；生产刀线/折线的专色名称、线宽与叠印规则由印厂确认。PDF OCG 图层与印刷专色/叠印不是同一个能力，必须分别验证。CMYK 转换不等于 PDF/X 合规，也不自动等于正确 ICC soft-proof；只有具体工具链生成并经过独立预检的结果，才标记相应能力。

有效 PPI 按最终放置尺寸计算：pixelWidth / (placedWidthMm / 25.4)，高度同理，取最差方向并计入裁剪/缩放。拟定默认阈值 300 PPI，可由印厂配置；低于阈值警告或阻断，不能把 PDF metadata 改成 300 就算提高分辨率。浏览器 2048 像素预览不得直接放大当高 DPI 成品。字体必须有授权、能够嵌入/转曲，中韩文字进行缺字检测；缺字禁止静默替换。

例如 1,000×800 mm、600 PPI 的完整 RGBA 位图约 23,622×18,898 像素，单份像素缓冲约 1.79 GB（十进制），尚未计入中间层。因此高 DPI 需要分块/流式、像素预算与独立任务内存限制，不能让小服务器同时展开多个全尺寸画布。这是尺寸公式估算，不是实测性能承诺。

制造准入

服务器检查：模板来源许可、审核有效范围、无未批准 cutApprox/bleedApprox、参数与厚度适用、几何/出血/安全区、字体/PPI/色彩预检、必要实物打样记录和审核权限。manufacturingReady 从审核证据派生，不能由普通前端字段设置。阻断时仍可按策略导出带标识校样，但不能通过改 format 或绕过 UI 下载生产文件。

研究未取得对方完整 CMYK/ICC 成品，本项目不把这些未知项隐藏掉；它们是独立开发、独立验证的交付门槛。[R07][T03]

16｜安全、权限与数据生命周期

同域会话默认方案：Django Session + HttpOnly/Secure cookie + CSRF。登录端点本身必须防 CSRF，不能只依赖 DRF 对已认证请求的检查；密码重置、注册和登录限流分别定义。启用 DEBUG=false、明确 ALLOWED_HOSTS/CSRF_TRUSTED_ORIGINS；只在可信 Caddy 链路下启用 SECURE_PROXY_SSL_HEADER。这些部署设置需要随生产配置实际检查。[O03]

所有 Design/Revision/Asset/Job/Cart/Order/Export 查询按 org 与权限过滤，既检查 URL 对象，也检查 body 中引用的 asset_id/revision_id。不能仅在前端隐藏按钮。服务端忽略客户提交的 owner、role、org_id、余额、价格和审批结果。

上传限制拟定：单文件 25 MB、单图不超过 50 MP、总请求 32 MB；这是首期业务策略而非目标站规格，需按样本调整。校验真实文件签名，拒绝伪扩展名、解压炸弹、超像素图、SVG 脚本/外链/foreignObject。原图隔离，净化派生图再提供给画布。首期上传 PNG/JPEG/WebP；SVG/字体等额外类型须经过专用净化和许可策略。私有文件只能鉴权下载或短期签名访问，不能把整个 media 卷挂给 Caddy file_server。

在生成/导出任务中设置软硬超时、最大图层/路径/像素/文件数。转换进程使用参数数组、禁 shell 拼接、无额外网络权限和最低文件访问范围。节点服务输入仅为白名单模板和数字参数，不运行用户提交的模板源码。支付 Webhook 使用供应商签名/时间窗/唯一事件；邮箱 OAuth 使用 state/PKCE 等正式流程，不能按未验证邮箱自动合并账户。

资产删除先检查引用：软删除设计不立即删除历史订单依赖；清理任务只处理已过保留期且无引用对象，生成审计。备份包含数据和私有文件，不包含未经授权的第三方 research 样本作为产品资产。研究目录可能包含登录截图/身份线索，生产镜像与公开站点不打包该目录。

    }

    handle @files {

    }
    handle {

        file_server
    }
}

这里使用 handle，不是 handle_path：后端路由需要收到完整 /api/v1/...；handle_path /api/* 会去掉 /api 前缀。API 与 SPA fallback 使用互斥 handle，未知 API 继续由 Django 返回 JSON 404，不能变成 index.html。[O01][O02]

/static/ 由后端镜像中完成 collectstatic 的公共管理静态资源提供，可采用 WhiteNoise 或单独静态卷；不要把用户私有上传混进去。Caddy 的上传体上限与 Django/业务限制同时配置。生产设置 SITE_ADDRESS 为正式域名，完成 DNS 与 80/443 可达；本地可用 http://localhost 配合开发覆盖配置。不要在原服务器已有 Caddy 占 443 时再抢同一端口；共用网关时应由现有 Caddy 按域名转发到内部应用网络。

17.4 同一 Caddy 内的静态文件、缓存与 SPA 回退

仅使用上面这一份 Caddyfile。API/admin/static、私有 media、Vue assets 和 SPA 使用互斥 handle；API 错误不会进入 index.html。带扩展名的静态文件缺失直接返回 404；路由约定不使用带点的末段。hash 命名的 /assets 文件长期缓存，index.html 与其他资源要求重新验证。静态根目录仅为 /srv 中的 dist，不包含源码、.env、研究材料或 Git 历史。

Django /static 由 backend 镜像执行 collectstatic 并通过 WhiteNoise 提供，私有 /media 不挂到 Caddy。不要再增加第二个静态服务器、frontend 运行服务或覆盖 /srv 的持久化卷。只有 Caddy 证书 /data、/config 持久化，前端文件随镜像版本发布。

生产 build context 配合 .dockerignore 排除 .git、.env*（保留示例）、node_modules、缓存、数据库/用户文件、研究大资源和测试输出；不能误排除 src/catalog、模板或当前 public 必需材质。前端 VITE_API_BASE=/api/v1 为非秘密构建参数；任何 VITE_* 都按浏览器可见处理。backend 镜像必须包含固定 Python 依赖、Gunicorn、migrations、生产设置和可用静态资源；geometry 镜像包含同源算法和固定 Node 依赖，禁止运行时在线抓目标站数据。

Node 的 vue-build 只在 docker build 中执行，最终 runtime 继承 Caddy 官方启动命令，不含 Node/npm 运行依赖。Vite 必须以域名根路径 / 构建（检查 vite.config.js 的 base），GITHUB_PAGES=0 是否生效以实际源码核对；浏览器请求同域 /api/v1。构建不注入任何私密 VITE_* 参数。

21｜性能、成本与运维可观测性

首期容量假设

以少量内部/早期客户、外部 AI API、少量并发设计为假设，先以约 4 vCPU / 8 GB RAM 的测试环境进行压测；这是测量起点，不是容量保证或购买报价。高 DPI 导出应串行/独立 worker 或限制画布大小。大目录、巨大路径数或更多并发用户需要重新测量，不能因为几个人使用就忽略位图内存。

普通 CRUD 的 p95、任务队列等待、首屏、首次 3D、尺寸重算和纹理刷新分别计量。建议目标在固定测试数据和设备上设定：一般 API p95 < 500 ms（不含 AI/导出）；交互型参数重算尽量在 200 ms 量级内；未达标时使用 debounce/Web Worker/缓存，但不能改变算法结果。这些是拟定验收目标，需通过实际样本校准。

成本模型，不虚报实时价格

月成本 = 云服务器 + 数据库/备份存储 + 对象存储 + 出网流量
       + AI成功调用费用 + 计费失败/重试费用 + 邮件/可选支付费用
单次AI预算 = 供应商计费 + 重试/处理开销 + 结果存储与流量

控制项包括组织月额度、用户/组织并发、单图尺寸、单次生成数、每日预算上限、结果保留期、导出最大像素和下载流量。AI 供应商价格在接入时读取官方当期报价并版本化，不在本文写未经核实的固定单价；后台要能按 provider/model/job 追踪实际支出与业务配额差异。

监控与日志

日志关联 request_id / job_id / design_id / revision_id，避免完整 prompt/客户资料/凭据长期进入普通日志。关键指标：API 5xx/延迟、队列长度与等待、任务失败分类、worker 心跳、配额冻结未结算、数据库/磁盘空间、导出像素与内存峰值、邮件失败、备份成功与恢复演练。异常报警需要可执行处理步骤，不只“出错了”。
