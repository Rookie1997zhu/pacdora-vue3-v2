三、技术架构与部署硬约束
1. 前端保留 Vue 3；现有 JS 几何与工具可以继续使用，新模块采用 TypeScript，渐进引入 Router、Pinia、Konva。保留现有 Three.js，不迁移 React/Next，不一次性全仓 TS 重写。
2. 后端采用 Django REST Framework + PostgreSQL；Redis/Celery 承担异步；使用 Node 内部几何服务复用同一份现有 JS 核心，不另写一套长期分叉的 Python 刀版公式。
3. 单一 Docker Compose 下有独立 caddy、backend、postgres、redis、geometry、worker、scheduler 服务；不创建独立 frontend 运行容器；迁移是受控单次服务，重型印前 worker 可按需独立。
4. 公网统一入口必须是 Caddy，不擅自换 Nginx。只有 Caddy 映射 80/443；同域 /api/v1 原样反向代理到独立 Django API，Vue dist 由 Caddy 直接 file_server 托管于 /srv。Django 路由保留 /api，不用 handle_path 错误去掉前缀。
5. deploy/Dockerfile.caddy 使用 Node 多阶段构建，仅在构建阶段执行 npm ci/npm run build；将 dist COPY 到最终 Caddy 镜像 /srv。生产仅运行 Caddy，不运行 Node/Vite 前端服务。只改前端执行 docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build --no-deps caddy，不重建数据库；证书卷保留。
6. Caddy 证书、PostgreSQL、资产使用持久化卷；私有 media 不直接 file_server。后台、几何、Redis、数据库不对公网裸露。
7. 支持本地开发和普通 Linux Compose 独立部署，不依赖 ChatGPT Sites 或特殊平台身份。

读取 scripts/check-all.mjs 及实际所有检查脚本，建立原始构建/测试基线。已有失败要如实登记，不能删除断言或跳过测试把状态改绿。保留 GitHub Pages 静态演示构建；演示环境不伪装具备云保存/AI/订单。

五、需实现的网站与后端业务
1. 自有品牌首页、产品目录、产品详情、尺寸/材料/数量配置、Studio 入口；后台可管理产品、模板能力与上下架。
2. 注册、登录、退出、密码重置、资料、组织/成员/角色；同域 Session + CSRF，登录自身也防 CSRF。
3. 我的设计、设计复制/归档/恢复、不可变版本、自动保存、并发冲突、硬刷新/重登录复开。
4. Studio 左侧 AI/背景/上传/文本/元素/图层；移动缩放旋转、裁剪、锁定可见、排序、复制删除、撤销重做；中韩文案完整。
5. 2D 和 3D 共用 DesignDocument；普通面板图层 panel_mm 与整展开图 net_mm 区分。统一面板/净刀版/像素/UV 变换，不用截图代替可编辑数据。折叠/相机是视图态，不改生产版本。
6. 模板改尺寸按 keep_mm/scale_with_panel/anchor 迁移图层；主区域生成图绑定 geometryHash，结构变动不得无提示拉伸；丢失 panel 的图层必须可恢复。
7. 真实 AI 图片生成和主区域包装设计是两条 operation。主区域需可信刀版和明确配准 masks，不是普通文生图改按钮名。保存生成历史、父子编辑链、应用结果与对应 revision。
8. 上传、去背景、矢量化、局部编辑、裁剪都有真实结果与状态；SVG 矢量化不能包装位图冒充，去背景不能刷白冒充透明。
9. 真实后端报价规则、Quote 明细与有效期、购物车、询价/订单、设计 revision 快照和后台审核。研究没有对方真实价格公式，禁止猜测成事实；没有正式规则显示待报价，不返回假价或 0 元。
10. 订单固定 design_revision/quote/材料/尺寸/金额快照，后来编辑设计不能改变历史订单。支付默认 manual_quote；无商户配置不伪造支付成功。需要外部凭据的集成正常记录 Blocked，核心本地闭环继续完成。
11. 异步导出与下载、明确质量等级、后台制造审批、预检报告、通知和审计。Django Admin 必须真的能管理相关业务，不是只有 API 名称。

六、数据与可靠性要求
1. 实现 User/Organization/Membership、Product/TemplateVersion/Approval、Design/Revision/ViewPreference、Asset/Derivative/Reference、AiJob/ExportJob、UsageReservation/Ledger、OutboxEvent、PricingRuleVersion/Quote、Cart/Order、Audit/Notification 等实际模型、迁移、索引与约束。
2. 业务文档为可校验、版本化 JSON；不要用 Konva stage JSON 或 Three 对象树作为唯一数据模型。图片引用私有 asset ID，不保存临时 Blob URL 当永久数据。
3. 所有对象操作与对象引用都验证 org/归属。不能只在前端隐藏按钮。客户端提交的 owner/role/org/价格/配额/审批标记不能直接生效。
4. 保存使用 expected_row_version + Idempotency-Key；同键同请求返回原结果，冲突 409；不可变 revision 与 current_revision 更新事务化。避免在长数据库锁中做远程 AI。
5. 创建任务、冻结配额与 outbox 同事务；Celery 至少一次投递下依靠 job 状态/租约和流水幂等；任务事实保存在 PostgreSQL，不只保存在 Redis。
6. 限制排队/执行超时与重试；未知供应商请求结果先对账，不无限重试计费；取消竞态、任务重启、队列丢失都有补偿路径。
7. AI 未配置返回明确能力不可用；禁止 setTimeout、mock 图片、本地假 API、硬编码成功状态出现在正式实现中冒充已完成。测试 fixture 可以存在但与真实冒烟证据分开。
8. 默认实现一个真实图像 API 适配器，按官方当前文档校验能力；模型和参数在后台配置，不假定同一个供应商支持全部后处理或 seed。缺少实际 key 时仍完成适配器与测试，但真实调用标记 Blocked。
9. 同一份几何核心在前端与 Node 服务对同参数输出一致；正式 API 未知模板/非法数字不得静默回落或夹取。

七、几何与制造边界
1. 固定几何 snapshot、modelOnly、自有参数模板必须分开。保留当前 geomMode 参数锁定，不能把 47 条目录全部宣称为任意尺寸可变。
2. README 的“仅尺寸导入”与实际 pacdoraGeomKnife/public/shipping-geom 路径要以代码核对，登记来源与授权，不偷偷删除旧功能，也不默认获得商业复用权。
3. 增加 crash-lock/mailer/sleeve/tray/pillow 的真实能力时，基于自有或获授权结构；pillow 曲面和多件拓扑单独实现，不用平面矩形或圆柱改名冒充。
4. validation.ok / productionReady 不等于 manufacturingReady。已有 cutApprox、bleedApprox、示意闭合、补偿参数与 BLEED_EXTRA_MM=10 必须登记并审阅；不要通过删 DEMO 水印把概念几何标成投产。
5. 当前 toPdf 缺少明确 mm->pt 的生产尺度链；新增 1:1 输出使用 mm*72/25.4，并做标尺与独立读取验证。SVG 要声明物理 mm；DXF/EPS 要实际可读与尺度检查。
6. 导出分 preview/vector_proof/manufacturing。只有真实预检和审核通过才允许 manufacturing；字体授权/缺字/嵌入、有效 PPI、出血、安全区、专色、OCG、CMYK/ICC 分别验证。RGB PDF 不能标 CMYK，改扩展名不能标原生 AI。
7. 不调用 Packative/Pacdora 的私有生产 API、不复制 EngView CAD 服务、不把研究快照当完整已验证公式，不把缺失证据填成 Passed。
