BOXCRAFT 刀版工作经验总结

参数化刀版工作台 · 从“刀版不准”到“按保真度把关”的全过程 · 2026-11-18（2026-11-19 补充保存与导出实测，见第九节）

一、问题的根源

最初工作台的刀版和 Pacdora 差别很大，原因只有一个：爬下来的盒型只保留了长宽高，然后按关键词套了一个通用模板。几百种结构被十几个通用模板“代表”，自然不准。

3D 是用刀版折出来的，刀版不准，3D 也跟着乱。

3D 错乱不用单独修，刀版对了它大部分就对了。

二、最终有效的做法

  1. 一盒一规格。不再靠人写模板，而是用编译脚本把每个 Pacdora 样本自动转成“结构规格”（面片树、尺寸表达式、轮廓、内部切线、折叠步骤），每个盒型一个 spec-<编号> 模板。
  2. 用保真度打分把关。每个盒型生成的刀版都和 Pacdora 原样本对比打分，分三档：精确、接近的可以定制尺寸；不达标的不允许定制。
  3. 不达标就锁定，不硬凑。不达标的盒型改为“固定规格”，原样回放 Pacdora 的刀版，尺寸不能改（11-19 起可按原规格保存和导出，见第九节）。宁可少一个可定制盒型，也不放一个不准的出去。
  4. 3D 用 Pacdora 自己的折叠步骤。把样本里的折叠动画编译成折叠配方，而不是自己猜折法。
  5. 按盒型懒加载规格。几百个规格不打进主包，打开哪个加载哪个。
第 3 条是整个质量保证的核心。

四、走过的弯路

  • 自动推导内部切线。试了两次，都会多切。最后改为直接从样本里提取切线，再逐盒验证保留或丢弃。
    教训：能从原始数据拿的，不要自己推。
  • 关键词重映射模板。盒型有了结构代码之后，旧的关键词映射反而把 6 个托盘盒映射错了。
    教训：有精确依据后，要关掉模糊规则。
  • 补爬样机 3D 模型。技术上做通了（46 个），但做出来才发现这类成品样机（彩带、抽屉、提手）不是需要的东西，最后全部撤掉。
    教训：批量做之前先出一个样品确认方向。
  • 同一编号在不同类目是不同刀版。缓存和加载只按编号会串盒，12 个盒型曾加载到别的类目的刀版。现在按“类目 + 编号”区分。

五、已确定的范围和口径

  • 只保留能折成纸盒的刀版（瓦楞纸质感那种）。没有折线的成品样机（46 个）、多层精品盒（8 个）不进目录；另有 1 个因参考刀版残缺下架（见第九节），共 55 个，名单在 src/catalog/excludedPresets.js。数据库里是归档而不是删除，删掉名单中的某一行并重新导出、写入种子即可恢复。
  • 工作台里的 7 个内置示例（直插舌盒、自锁底盒、飞机盒、FEFCO 0201 等）只是示例，不在修复范围内。
  • Pacdora 几何数据的商用授权已确认没有问题。

七、还没解决或没验证的

登录后的流程只测了一部分。工作台的保存和导出已于 11-19 用测试账号实测（范围见第九节）；Studio 图案设计整页、产品页进入设计器的流程仍没有逐个测。
  • 后端测试只跑了 test_assets_designs 和 test_exports 两组。
  • 天地盖类盒型的部件标签（底盖 / 天盖）可能标反。
  • 整体尺寸标注文字偶尔会和面片标签重叠。
  • LAB 列表页会发出几百个 404 探测请求。
  • “主力盒型清单”待挑选。 已定为 96 个（docs/主力盒型清单.csv），并已做多尺寸采样，见第九节。
  • Illustrator 打开导出的 .ai 是否显示为图层，没有验证（手边没有 Illustrator）。
  • 产品目录 273 个产品中，有 84 个被比对脚本判为“与原图不重合（同结构不同尺寸）”，这个判断没有人工逐个确认。
  • 可定制模板 608 个，页面上的导出只实测了 5 个；其余只有 check:all 的几何校验。
  • 固定规格只检查了“能导出、尺寸自洽、图层齐全”，没有逐个对照参考图看形状。
  • 盒型 111640 的参考数据自报总高 489 mm，几何实际 492 mm，差 3 mm 的原因没查明。
  • 云端部署时 deploy/env.example 新增的配置项没有和云端 .env 逐项核对。

八、几条通用经验

  1. 先查原因再动代码。第一轮要求“先不要动代码”，结果定位到的根因和最初直觉完全不同。
  2. 质量靠可度量的门槛，而不是逐个目测。打分脚本写出来之后，后面所有改动都有了客观依据。
  3. 不准的宁可不给。锁定回放比放出一个错的刀版安全得多，印刷出错的代价远大于少一个盒型。
  4. 批量做之前先出一个样品确认方向。
  5. 标着 1:1 不等于真是 1:1。PDF 一直写着“1:1”，实际只有约 35%，直到在页面上导出并量了尺寸才发现。标注和实际要各验一次。
  6. 量尺寸要把弧线算进去。只取路径端点会漏掉弧线鼓出去的部分，第一遍因此误报了 26 个“尺寸不一致”，还把一个插舌误判成了孔位。
  7. 批量测直接调服务。逐个走页面既慢又会触发限流、消耗导出额度；页面流程抽测几个，其余用同样的请求直接打服务。
  8. 同一类错误要全量扫一遍。发现一个盒型高度采成 0 之后，扫了全部 971 个参考文件，确认只有这一个，才敢下结论。
  9. 改动要及时提交。几个会话的改动一直没提交，一条误敲的 git stash 就把 49 个文件全部带走，还把旧代码部署了上去。恢复只花了几分钟，但本不该发生。

九、2026-11-19 补充：保存与导出实测

这一轮用测试账号把工作台的保存和导出在页面上实际走了一遍，并批量测了固定规格。以下只写实际做过的。

当前目录

  • 工作台共 736 个模板：608 个可定制，128 个固定规格（折叠盒、托盘盒、礼盒、方形盒四类加内置示例）。
  • 主力盒型定为 96 个。按尺寸插值的模板（用多个尺寸的参考样本做插值）在 101 个模板中启用了 67 个，其余因刀版结构随尺寸变化，仍用原来的规格模板。改了尺寸的刀版只在已验证的尺寸范围内可信。

下架一个参考数据残缺的盒型

托盘盒 110440（斜边自锁底手提盒）的参考刀版高度是 0：四面侧板没有高度，只剩底部折片。按正常高度向来源重新取了 4 次，长宽会变，高度始终返回 0，所以拿不到正确的刀版。已加入排除名单（原因标为 broken）并从数据库删除对应模板。

参考数据本身也可能是错的。保真度打分是“和样本比”，样本错了分数照样是满分，所以这个盒型一直没被发现，直到看 3D 才暴露。

上云不需要导出导入刀版数据

刀版几何是仓库里的文件（public/*-geom/、public/sampled/），构建时打进镜像；数据库里只有模板登记表，由 seed_catalog 生成，可重复执行。这一轮没有数据库结构变更。

拉取代码→ 重建 caddy / geometry / backend / worker / scheduler→ seed_catalog

docs/pacdora-multisize/（77 MB 原始采样）没有入库，换机器重新生成插值模板需要重新采样。
